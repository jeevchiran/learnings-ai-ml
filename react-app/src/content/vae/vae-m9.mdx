## Generating 2D Latent Manifolds

When a VAE is trained with a 2D latent space ($z = [z_1, z_2]$), we can visualize the entire learned data manifold by creating a uniform grid across the prior domain (e.g. $z_1, z_2 \in [-2.5, +2.5]$) and decoding each coordinate:

<LatentManifoldWidget />

```python
# Code snippet: Creating a 2D Manifold Grid in PyTorch
@torch.no_grad()
def plot_latent_manifold(model, grid_size=15, z_range=2.5):
    model.eval()
    # Create coordinate grid
    z1 = torch.linspace(-z_range, z_range, grid_size)
    z2 = torch.linspace(-z_range, z_range, grid_size)
    grid_x, grid_y = torch.meshgrid(z1, z2, indexing='xy')
    
    # Flatten into (grid_size^2, 2)
    z = torch.stack([grid_x.flatten(), grid_y.flatten()], dim=-1)
    
    # Decode full meshgrid in one forward pass
    reconstructions = model.decode(z).view(-1, 28, 28)
    return reconstructions
```

## Latent Space Interpolation: Lerp vs Slerp

A straight line between two points on a sphere cuts through the inside. In high dimensions that interior is almost empty of training mass, so midpoints of a linear interpolation are systematically more "unusual" than their endpoints — which often shows up as washed-out, low-contrast samples halfway through a morph.

Spherical interpolation (**slerp**) walks *along* the shell instead, keeping the radius roughly constant so every intermediate code is as typical as the endpoints. In 2D the difference is negligible; by 64 dimensions it is very visible.

</PredictReveal>


How should we traverse the path between two encoded images $x_A$ and $x_B$?

### 1. Linear Interpolation (Lerp)

The simplest trajectory is a straight line:

$$z(\alpha) = (1 - \alpha) z_A + \alpha z_B, \qquad \alpha \in [0, 1]$$

While effective in 2D or low dimensions, in high dimensions (e.g. $d = 64$ or $128$), the straight line between two points passes close to the origin $z = 0$, where the density is much higher than the spherical shell where high-dimensional Gaussians naturally concentrate (the **Gaussian Annulus Theorem**).

### 2. Spherical Linear Interpolation (Slerp)

In high-dimensional Gaussian spaces, points sampled from $\mathcal{N}(0, I_d)$ have Euclidean norm concentrated near $\|z\| \approx \sqrt{d}$. **Slerp** moves along the constant-radius hypersphere arc:

$$z(\alpha) = \frac{\sin((1-\alpha)\Omega)}{\sin(\Omega)} z_A + \frac{\sin(\alpha\Omega)}{\sin(\Omega)} z_B, \qquad \text{where } \cos(\Omega) = \frac{z_A \cdot z_B}{\|z_A\| \|z_B\|}$$

Slerp preserves vector norm and prevents the interpolation from traveling through atypical low-norm regimes.

## Vector Arithmetic in Latent Space

Because representations are continuous and linearly aligned, we can discover **semantic attribute vectors** by averaging latent codes:

$$v_{\text{smile}} = \frac{1}{N_{\text{smile}}} \sum_{i \in \text{smiling}} z_i - \frac{1}{N_{\text{neutral}}} \sum_{j \in \text{neutral}} z_j$$

Adding this attribute vector to a new face code modifies the feature predictably:

$$z_{\text{new}} = z_{\text{input}} + \gamma \cdot v_{\text{smile}}$$

```
  [ Neutral Face x ] ──► Encoder ──► z_neutral
                                         │
                                         ▼  + γ · v_smile
                                      z_smiling
                                         │
                                         ▼  Decoder
                                  [ Smiling Face x̂ ]
```

<ConceptBox title="TL;DR">
- A trained decoder maps *any* latent coordinate to an image, so the latent space can be explored directly — sweep a 2D grid and every cell produces an output, though unrealistic or poorly learned regions can remain.
- **Interpolating** between two codes produces a smooth semantic morph rather than a pixel crossfade, because the path passes through regions the KL term kept populated.
- In higher dimensions prefer **slerp** over **lerp**: Gaussian mass concentrates on a shell at roughly constant radius, and a straight line cuts through the sparse low-density interior.
- Latent directions can carry consistent meaning, so **vector arithmetic** on codes can add or remove an attribute.
