## The generative story

<PredictReveal
  prompt="You want a model that can invent new handwritten digits. Which description better matches how a generative latent-variable model produces one?"
  options={[
    "Look up the closest training image and modify a few pixels",
    "Roll dice to pick a hidden code describing what to draw, then let a network turn that code into an image"
  ]}
  correct={1}
>

The model assumes data comes into existence in two steps, and this assumption is called the **generative story**:

1. Draw a hidden code from a simple, fixed distribution — the **prior**:
   $$z \sim p(z) = \mathcal{N}(0, I)$$
2. Turn that code into data using a network with weights $\theta$ — the **likelihood**:
   $$x \sim p_\theta(x|z)$$

```
     p(z) = 𝒩(0, I)          Step 1: roll dice for a hidden code
         │
         ▼
     ┌───────┐
     │   z   │               The latent code from Module 1
     └───────┘
         │
         ▼  Decoder network p_θ(x|z)    Step 2: turn the code into data
     ┌───────┐
     │   x   │               A generated image
     └───────┘
```

Nothing here is new machinery — step 2 is the decoder, and $p(z)$ is the standard normal region Module 2 wanted every code pulled toward. The probability notation just makes the assumption explicit enough to optimise against.

</PredictReveal>

## The quantity we want, and why we cannot have it

To fit $\theta$, the natural target is the probability the model assigns to the real training data — high probability on real data means a good model. Because $z$ is hidden, getting that probability means accounting for *every* code that could have produced $x$:

$$\log p_\theta(x) = \log \int p_\theta(x|z) p(z) \, dz$$

Read the integral as: *"add up, over every possible hidden code, the chance of drawing that code times the chance it produces $x$."*

<PredictReveal
  prompt="Why can we not just approximate that integral by sampling a few thousand random z values and averaging p(x|z) over them?"
  options={[
    "Because the normal distribution has infinite support",
    "Because in high dimensions almost every randomly drawn z produces something nothing like this specific x, so nearly every term in the average is essentially zero",
    "Because autograd cannot differentiate through an integral sign"
  ]}
  correct={1}
>

Random codes decode to random-looking outputs. For one *specific* target image, the overwhelming majority of sampled $z$ values give $p_\theta(x|z) \approx 0$, so the average is dominated by the vanishingly rare sample that happens to be relevant. Getting a usable estimate needs exponentially many samples as the latent dimension grows.

$$\int p_\theta(x|z) p(z) \, dz \approx \frac{1}{N} \sum_{i=1}^N p_\theta(x|z^{(i)}) \qquad \text{— useless unless } N \text{ is astronomically large}$$

</PredictReveal>

<Recall items={[
  { q: "Why does naive Monte Carlo sampling fail to estimate the marginal likelihood?", a: "In a high-dimensional latent space, almost every randomly drawn z decodes to something unlike the one specific target image x, so p(x|z) is essentially zero for nearly every sample. The estimate is dominated by rare relevant samples, and the number needed for a usable estimate grows exponentially with latent dimension." },
]} />

## The same wall, from the other side

If we cannot get $p_\theta(x)$ directly, the obvious alternative is to ask which codes *actually* produced a given $x$ — the **posterior** $p_\theta(z|x)$. Bayes' rule gives it:

$$p_\theta(z|x) = \frac{p_\theta(x|z) p(z)}{p_\theta(x)}$$

But the denominator is the same integral we just failed to compute. **The posterior is intractable for exactly the reason the evidence is**, so this route is closed too.

<PredictReveal
  prompt="Given that the true posterior cannot be computed, what is the pragmatic move?"
  options={[
    "Abandon latent-variable models entirely",
    "Train a second network to output an approximation of the posterior, and find some way to improve it without ever seeing the true one"
  ]}
  correct={1}
>

This is **variational inference**: replace the intractable $p_\theta(z|x)$ with a tractable stand-in $q_\phi(z|x)$ — a Gaussian whose mean and variance are produced by a network. That network is the **encoder** from Module 2, and this is what it was for all along.

```
   Target:        p_θ(z|x)   — intractable, unknown shape
                     ▲
                     │  make these as close as possible
                     ▼
   Approximation: q_ϕ(z|x) = 𝒩(μ_ϕ(x), Σ_ϕ(x))   — a network output, fully tractable
```

Which leaves one obvious problem: closeness is measured by $D_{KL}(q_\phi(z|x) \,\|\, p_\theta(z|x))$, and that formula contains the very posterior we cannot compute. Module 4 resolves this — and the resolution turns out to be the VAE's loss function.

</PredictReveal>

<ConceptBox title="TL;DR">
- The **generative story**: draw a hidden code $z$ from a fixed prior $\mathcal{N}(0, I)$, then generate $x$ from $p_\theta(x|z)$. Step 2 is just the decoder.
- Fitting the model means maximising $\log p_\theta(x) = \log \int p_\theta(x|z)p(z)\,dz$, but that integral is **intractable** — random codes almost never produce a given target image, so sampling estimates it uselessly.
- The **posterior** $p_\theta(z|x)$ is blocked by the same integral in its denominator, so that route is closed too.
- **Variational inference** substitutes a network-produced approximation $q_\phi(z|x)$ — the encoder — leaving one problem: measuring its quality seems to require the very posterior we cannot compute.
</ConceptBox>
