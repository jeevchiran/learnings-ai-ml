## Why force data through a bottleneck?

<PredictReveal
  prompt="You train a network to copy a 784-pixel image to an identical 784-pixel output, but every value must pass through a middle layer of just 2 numbers. What does the network have to learn to do this well?"
  options={["To memorise each training image and index them by the 2 numbers", "To find the handful of underlying factors that actually vary across the data, and describe each image by those"]}
  correct={1}
>

Two numbers cannot store 784 pixels. So the network cannot memorise — it has to discover what genuinely *varies* across the dataset and spend its tiny budget on that. For handwritten digits, that might be stroke thickness and slant; for faces, pose and expression. Everything else — the exact value of pixel 400 — gets reconstructed approximately from those few factors.

This is the central bargain: **a narrow bottleneck forces the network to learn structure instead of storage.** Widen the bottleneck to 784 and the pressure disappears — the network can just learn the identity function, passing pixels straight through, and learn nothing about the data at all.

</PredictReveal>

<Recall items={[
  { q: "Why does a narrow bottleneck force a network to learn something meaningful, while a wide one does not?", a: "A narrow bottleneck cannot physically hold the input, so the network must spend its limited capacity on the factors that actually vary across the dataset. If the bottleneck is as wide as the input, the network can simply learn the identity function — copying values straight through — which satisfies the objective while learning nothing about the structure of the data." },
]} />

## The three pieces of an autoencoder

An **autoencoder** is exactly that architecture, and it has three named parts:

<FactList accent="#6366f1" items={[
  { t: 'Encoder', d: 'A network that compresses the input x down to a small vector. Written z = f(x). Its job is to decide what is worth keeping.' },
  { t: 'Latent code (z)', d: 'The compressed vector itself — the bottleneck. Also called the latent representation or the code. This is what the whole track is ultimately about.' },
  { t: 'Decoder', d: 'A network that expands z back to full size, producing a reconstruction written x-hat. Its job is to rebuild the input from only what the encoder kept.' },
]} />

Training needs no labels at all. The target *is* the input: push $x$ through both networks and penalise the difference between what came out and what went in. That penalty is the **reconstruction loss**, typically squared error:

$$\mathcal{L}_{\text{recon}} = \| x - \hat{x} \|^2$$

In words: *take the reconstruction, subtract the original, square the differences, add them up.* A loss of zero means a perfect copy. Because the target is the input, no human ever has to label anything — which is why autoencoders are called **self-supervised**.

<Recall items={[
  { q: "What are the three components of an autoencoder, and what supervision signal does training require?", a: "An encoder that compresses x into a latent code z, the latent code itself (the bottleneck), and a decoder that reconstructs x-hat from z. Training requires no labels at all — the target is the input itself, and the loss measures the difference between the reconstruction and the original. This makes it self-supervised." },
]} />

## Latent space is a map

<PredictReveal
  prompt="Train an autoencoder on digits with a 2-number bottleneck, and plot where every training image lands on those two axes. Would you expect two images of the digit 3 to land near each other, or far apart?"
  options={["Near each other — similar inputs need similar codes to reconstruct similarly", "Far apart — the encoder has no reason to group anything"]}
  correct={0}
>

Because the decoder is a continuous function, two codes that sit close together decode to similar images. Run that backwards: for two similar images to reconstruct correctly, their codes generally end up close together too. So the 2D plane of possible $z$ values becomes a **map** of the data, with related things clustered.

That map is called the **latent space**, and it is the object of interest for the rest of this track. "Latent" just means hidden or not directly observed — nobody labelled these axes, and the network was never told what they should mean. They emerged from the pressure to compress.

</PredictReveal>

## Comparing two distributions, informally

One more idea is needed before the next module, and it is worth meeting gently now because the formal version arrives quickly.

Sometimes we need to say **how different one probability distribution is from another** — not how far apart two points are, but how far apart two entire *spreads* are. The standard tool for this is **KL divergence**, written $D_{KL}(q \,\|\, p)$.

For now, three properties are enough:

<FactList accent="#6366f1" items={[
  { t: 'It is zero when they match', d: 'If distribution q is identical to distribution p, the divergence is exactly 0. Any difference makes it positive.' },
  { t: 'It is never negative', d: 'The value only ever goes up from 0 as the distributions grow further apart. There is no such thing as a negative divergence.' },
  { t: 'It is not symmetric', d: 'The divergence from q to p is generally not the same number as from p to q, which is why it is called a divergence rather than a distance.' },
]} />

That is the whole intuition: **a non-negative number measuring how far one distribution sits from another, hitting zero only when they match.** Module 5 derives the exact formula for the Gaussian case; until then, reading $D_{KL}$ as "how far apart these two distributions are" is enough to follow the argument.

<Recall items={[
  { q: "What does KL divergence measure, and what value does it take when two distributions are identical?", a: "It measures how different one probability distribution is from another — a comparison of entire spreads rather than of two points. It equals exactly 0 when the distributions are identical, is never negative, and is not symmetric (the divergence from q to p is generally not the same as from p to q), which is why it is called a divergence rather than a distance." },
]} />

---

<ConceptBox title="TL;DR">
- A narrow **bottleneck** forces a network to learn the factors that genuinely vary in the data, because it physically cannot store the input. Widen it too far and the network just learns the identity function.
- An **autoencoder** is encoder → latent code $z$ → decoder, trained with a **reconstruction loss** comparing the output to the input. It needs **no labels** — the target is the input itself.
- The space of possible $z$ values is the **latent space**, a map on which similar inputs land near each other because the decoder is continuous.
- **KL divergence** $D_{KL}(q \,\|\, p)$ measures how far one distribution is from another: zero when they match, never negative, and not symmetric. The exact formula comes in Module 5.
</ConceptBox>
