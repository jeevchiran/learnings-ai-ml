## Why layers, and why they compose

<MitigationLayersWidget />

Grounding is the highest-leverage single intervention, and it is worth being precise about why: it changes the *class* of the problem. An open-domain factuality question (Module 2) becomes a closed-domain faithfulness question, which is checkable against supplied text rather than against all of world knowledge. That is a large win. But it introduces its own failure modes — retrieval returning nothing relevant, retrieving something outdated, or the model under-weighting a passage sitting in the middle of a long context (Module 4).

Each subsequent layer targets a residue the previous one leaves:

## Designing for the residue

<PredictReveal
  prompt="Every mitigation layer is enabled and the measured hallucination rate is low but non-zero. What does responsible design do with that remaining rate?"
  options={["Treat the system as solved and remove the surrounding controls, since the rate is now small", "Design the product around it — disclosure, visible sources, reversible actions, logging, and a path for users to challenge an output"]}
  correct={1}
>

Because the residue never reaches zero, the last layer is not a filter at all — it is product design. Concretely: show sources next to claims so verification is cheap rather than aspirational; prefer reversible actions and require confirmation before irreversible ones; log inputs and outputs so an error can be traced after the fact; give users an obvious way to report a wrong answer; and scope the deployment away from decisions where the severity tier from Module 2 exceeds what the measured rate can support.

That last point is the one most often skipped. Deciding *not* to deploy into a particular decision — or to deploy in an assistive rather than authoritative role — is a legitimate and frequently correct mitigation, and it is the only one that addresses the residue directly rather than shrinking it.

</PredictReveal>

<ConceptBox title="TL;DR">
- Layers compose because each targets a **different cause** from Modules 3 and 4 — they are not redundant copies of one control.
- **Grounding** is the highest-leverage single layer because it changes the problem class: open-domain factuality becomes checkable closed-domain faithfulness. It does not eliminate failure — it relocates it to retrieval quality and context handling.
- Decoding constraints, self-consistency, citation verification, guardrails, and human review each catch a residue the others leave; **human review is a scarce resource**, best spent on the high-severity tier rather than uniformly.
- The rate never reaches zero, so the final layer is **product design**: visible sources, reversible actions, logging, user challenge paths, and scoping deployment away from decisions the measured rate cannot support.
</ConceptBox>
