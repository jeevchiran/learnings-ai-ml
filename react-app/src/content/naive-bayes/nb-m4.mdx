## From Formula to Code

Module 3 derived $\hat{y} = \arg\max_y P(y)\prod_i P(x_i\mid y)$ and worked it by hand on the Play Tennis table. Here we implement exactly that — first from scratch, then with scikit-learn — on the *same* data, so outputs can be checked against each other.

## From Scratch

```python
from collections import Counter

data = [
    ("Sunny", "False", "No"), ("Sunny", "True", "No"),
    ("Overcast", "False", "Yes"), ("Rain", "False", "Yes"),
    ("Rain", "False", "Yes"), ("Rain", "True", "No"),
    ("Overcast", "True", "Yes"), ("Sunny", "False", "Yes"),
    ("Sunny", "True", "Yes"), ("Rain", "False", "Yes"),
]
classes = ["Yes", "No"]
outlook_vals = ["Sunny", "Overcast", "Rain"]
windy_vals = ["True", "False"]
alpha = 1  # Laplace smoothing, see Module 7

def fit(data):
    n = len(data)
    priors, outlook_lik, windy_lik = {}, {}, {}
    for c in classes:
        rows = [d for d in data if d[2] == c]
        n_c = len(rows)
        priors[c] = n_c / n
        # +alpha to every count, +alpha*|values| to denominator
        outlook_lik[c] = {v: (sum(1 for d in rows if d[0] == v) + alpha) / (n_c + alpha * len(outlook_vals)) for v in outlook_vals}
        windy_lik[c]   = {v: (sum(1 for d in rows if d[1] == v) + alpha) / (n_c + alpha * len(windy_vals)) for v in windy_vals}
    return priors, outlook_lik, windy_lik

def predict_proba(outlook, windy, priors, outlook_lik, windy_lik):
    scores = {c: priors[c] * outlook_lik[c][outlook] * windy_lik[c][windy] for c in classes}
    total = sum(scores.values())
    return {c: s / total for c, s in scores.items()}

priors, outlook_lik, windy_lik = fit(data)
print("priors:", priors)
print(predict_proba("Sunny", "True", priors, outlook_lik, windy_lik))
```

```
priors: {'Yes': 0.7, 'No': 0.3}
{'Yes': 0.4375, 'No': 0.5625}
```

Module 3's *unsmoothed* hand calc gave `{'Yes': 0.30, 'No': 0.70}`. The prediction (**No**) is unchanged, but Laplace smoothing (`alpha=1`) pulls both toward 0.5 — softening overconfidence by treating every category as seen at least once.

<ConceptBox title="The smoothing formula">
`(count + alpha) / (n_c + alpha * num_values)` adds a small pretend count to every category. With `alpha=1` (add-one), even a zero-occurrence category gets a small nonzero probability. Set `alpha=0` to reproduce Module 3's raw frequencies exactly.
</ConceptBox>

## The Same Model in scikit-learn

For categorical features, `CategoricalNB` is the identical algorithm — encode to integers, fit, compare:

```python
import numpy as np
from sklearn.naive_bayes import CategoricalNB
from sklearn.preprocessing import OrdinalEncoder

X_raw = [[o, w] for o, w, _ in data]
y = [c for _, _, c in data]

enc = OrdinalEncoder()
X = enc.fit_transform(X_raw)

clf = CategoricalNB(alpha=1.0)
clf.fit(X, y)

query = enc.transform([["Sunny", "True"]])
print("predicted class:", clf.predict(query)[0])
print("class probabilities:", dict(zip(clf.classes_, clf.predict_proba(query)[0].round(4))))
```

Reproduces the from-scratch result — class `No`, probabilities matching `{'Yes': 0.4375, 'No': 0.5625}`. The from-scratch version's value isn't speed; it's proof that `CategoricalNB` is the same three-line counting formula, vectorized and hardened.

## A Realistic Dataset: Gaussian NB on Iris

Real numeric features need a continuous likelihood (Module 5). Preview — same `fit → predict` pattern with `GaussianNB`:

```python
import numpy as np
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.naive_bayes import GaussianNB
from sklearn.metrics import accuracy_score

X, y = load_iris(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42)

clf = GaussianNB().fit(X_train, y_train)
y_pred = clf.predict(X_test)

print("test accuracy:", round(accuracy_score(y_test, y_pred), 4))
print("class priors:", np.round(clf.class_prior_, 3))
print("first test posterior:", np.round(clf.predict_proba(X_test[:1]), 4))
```

```
test accuracy: 0.9778
class priors: [0.295 0.352 0.352]
first test posterior: [[0.     0.9955 0.0045]]
```

Two things: `class_prior_` isn't exactly `[1/3,1/3,1/3]` — it's the *empirical* class fraction in the training split, matching "count the labels". And the posterior is nearly one-hot (99.55%) — Gaussian NB tends to produce sharply-peaked, overconfident posteriors (Module 6).

Both demos picked their likelihood by feature type: counts for categorical Outlook/Windy, a Gaussian for continuous Iris. That choice is the whole content of Module 5 — Multinomial, Bernoulli, and Gaussian as three answers to "what does $P(x_i\mid y)$ look like?"
</Bridge>

## Practice

#### Problem 1: Smoothing and Confidence
As `alpha` grows very large (e.g. 1000), what happens to `predict_proba`?

**Solution:** Each likelihood approaches uniform ($1/|\text{values}|$) regardless of data — the likelihoods stop discriminating, and predictions collapse toward the priors alone (`{'Yes': 0.7, 'No': 0.3}`). Large `alpha` trades data signal for a uniform prior over feature values: useful against overfitting on tiny data, harmful in excess.

#### Problem 2: Independence in Code
For query `("Rain", "False")`, what do the two likelihood factors reveal about how independence is applied?

**Solution:** Yes: $(3{+}1)/(7{+}3) = 0.4$ and $(5{+}1)/(7{+}2) = 0.667$, so $0.7 \times 0.4 \times 0.667 \approx 0.187$. No: $(1{+}1)/(3{+}3) = 0.333$ and $(1{+}1)/(3{+}2) = 0.4$, so $0.3 \times 0.333 \times 0.4 \approx 0.04$. The code never builds a joint (Outlook, Windy) table — it multiplies two independently-looked-up scalars. That multiplication *is* the independence assumption: there's no code path to represent "Rain and calm co-occur more than their marginals predict."
