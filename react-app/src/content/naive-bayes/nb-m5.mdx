## Same Skeleton, Different Likelihood

Every variant uses the identical rule from Module 3:

$$\hat{y} = \arg\max_{y} \; P(y) \prod_{i=1}^{n} P(x_i \mid y)$$

Only the assumed *shape* of $P(x_i \mid y)$ changes — and it should match how the feature was generated:

| Variant | Feature type | Likelihood | Typical use |
|---|---|---|---|
| Multinomial | non-negative counts | Multinomial | text via word counts |
| Bernoulli | binary 0/1 | Bernoulli | text via word presence |
| Gaussian | continuous | Normal | measurements, sensors |

## Multinomial NB

For **counts** (how many times each word appears). With word counts $x_1,\ldots,x_n$:

$$P(\mathbf{x}\mid y) \propto \prod_{i=1}^{n} \theta_{y,i}^{\,x_i}$$

where $\theta_{y,i} = P(\text{word } i \mid y)$, estimated with Laplace smoothing:

$$\theta_{y,i} = \frac{N_{y,i} + \alpha}{N_y + \alpha n}$$

$N_{y,i}$ = count of word $i$ in class-$y$ docs, $N_y$ = total words in class $y$, $n$ = vocabulary size.

```python
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB

docs = [
    "buy cheap pills now", "limited offer buy now",
    "meeting scheduled for tomorrow", "project deadline tomorrow",
    "cheap meds buy now", "lunch meeting tomorrow project",
]
labels = ["spam", "spam", "ham", "ham", "spam", "ham"]

vec = CountVectorizer()
X = vec.fit_transform(docs)          # word-count matrix (6 docs, 14 vocab words)

mnb = MultinomialNB(alpha=1.0).fit(X, labels)
test = vec.transform(["cheap buy now"])
print(mnb.predict(test))                  # ['spam']
print(mnb.predict_proba(test).round(4))   # [[0.0229 0.9771]]  -> P(ham), P(spam)
```

97.71% spam — "cheap", "buy", "now" are all disproportionately spammy, and the multinomial likelihood multiplies that evidence.

## Bernoulli NB

For **binary presence/absence** — did the word appear, ignoring count. Each $x_i \in \{0,1\}$:

$$P(x_i \mid y) = p_{y,i}^{\,x_i} \,(1-p_{y,i})^{\,1-x_i}$$

Crucially, Bernoulli NB also penalizes *absence*: a vocabulary word missing from the document still contributes a $(1-p_{y,i})$ factor. Multinomial only multiplies in words that actually occur.

```python
from sklearn.naive_bayes import BernoulliNB

bnb = BernoulliNB(alpha=1.0).fit(X, labels)   # binarizes counts to 0/1
print(bnb.predict(test))                  # ['spam']
print(bnb.predict_proba(test).round(4))   # [[0.0013 0.9987]]  -> P(ham), P(spam)
```

Even more extreme (99.87%) — it also credits the *absence* of ham words like "meeting"/"tomorrow" as evidence against ham.

<ConceptBox title="Multinomial vs Bernoulli, concretely">
"buy buy buy now": Multinomial sees "buy" ×3 as three pieces of evidence; Bernoulli sees only "buy present" — one occurrence and a hundred look identical. Choose Multinomial when frequency carries signal; Bernoulli when only occurrence matters (short texts, rare keywords).
</ConceptBox>

## Gaussian NB

For **continuous** features. Each is normal within each class, with per-class mean and variance:

$$P(x_i \mid y) = \frac{1}{\sqrt{2\pi\sigma_{y,i}^2}} \exp\left(-\frac{(x_i - \mu_{y,i})^2}{2\sigma_{y,i}^2}\right)$$

$\mu_{y,i}$ and $\sigma_{y,i}^2$ are just the sample mean and variance of feature $i$ over the class-$y$ rows — one small Gaussian per (class, feature).

```python
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.naive_bayes import GaussianNB

X, y = load_iris(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42)

gnb = GaussianNB().fit(X_train, y_train)
print(gnb.theta_.round(2))   # per-class, per-feature means  (3 classes x 4 features)
print(gnb.var_.round(2))     # per-class, per-feature variances
```

`gnb.theta_[k,i]` is $\mu_{y=k,i}$ and `gnb.var_[k,i]` is $\sigma_{y=k,i}^2$ — just twelve means and twelve variances, computed by averaging within each class.

<ConceptBox title="Choosing the variant">
- **Continuous** (length, temperature, pixels) → Gaussian. If badly non-normal, transform (log/Box-Cox) or bucket into categories.
- **Counts** (word frequencies) → Multinomial. The bag-of-words default.
- **Binary flags** (present/absent) → Bernoulli. Better than Multinomial for short docs or when absence is informative.
- **Mixed types** → fit separate NB models per feature group, combine log-probabilities (Module 6).
- **Unsure on text** → try both Multinomial and Bernoulli with cross-validation; they rarely differ by more than a couple points.
</ConceptBox>

<Bridge>
Every formula multiplies many probabilities — one per feature. With ten features, fine; with ten thousand (a real vocabulary), the product of ten thousand sub-1 numbers underflows to exactly zero, silently breaking the classifier. Module 6 shows why and the log-space fix every production implementation uses.
</Bridge>

## Practice

#### Problem 1: Matching Variant to Data
(a) emails by word counts, (b) short SMS by keyword presence, (c) flowers by petal length/width in cm.

**Solution:** (a) Multinomial — counts map to the multinomial likelihood. (b) Bernoulli — binary presence, and short messages make counts uninformative. (c) Gaussian — continuous measurements match the normal likelihood.

#### Problem 2: Zero Count in Multinomial
"pills" appears only in spam, never ham. Without smoothing ($\alpha=0$), what is $\theta_{\text{ham},\text{"pills"}}$, and why is that a problem?

**Solution:** $\theta_{\text{ham},\text{"pills"}} = 0/N_{\text{ham}} = 0$. Any future ham email containing "pills" gets a ham likelihood factor of exactly zero — the whole ham product collapses to zero regardless of every other word, making that email impossible to classify as ham. This is why $\alpha=1$ is the scikit-learn default.
