## Advantages

<ConceptBox title="Where Naive Bayes genuinely wins">
- **Training is one counting pass.** Class frequencies for the prior, per-feature stats for likelihoods — no gradient descent, no convergence check. $O(Nn)$ and trivially parallel.
- **Prediction is fast.** One multiply (or log-add) per feature per class. No matrix inversion, tree traversal, or distance computation.
- **Data-efficient.** Each $P(x_i\mid y)$ is a small 1-D distribution, not a joint — reliable from far fewer examples than a model learning interactions. A strong baseline when data is scarce.
- **Handles high-dimensional sparse data.** A 50,000-word vocabulary is routine for Multinomial NB; most classifiers need dimensionality reduction first.
- **Naturally incremental.** New examples just update counts (or running mean/variance) — hence `partial_fit`.
- **Interpretable.** The log-space score decomposes into a per-feature attribution: which features pushed the score toward this class, by how much.
</ConceptBox>

## Disadvantages

<ConceptBox title="Where the independence assumption and simplicity cost you">
- **Independence is almost always false, and probabilities suffer.** Correlated features get double-counted (Module 3, Problem 2), making posteriors overconfident (near 0 or 1). The predicted *label* often survives; the predicted *confidence* usually shouldn't be trusted.
- **Zero-frequency problem.** An unseen (feature, class) pair gives an unsmoothed likelihood of exactly 0, which zeroes the whole class score. Laplace/add-$\alpha$ smoothing fixes it but must be enabled deliberately.
- **Poor calibration.** `predict_proba` is a ranking signal, not a trustworthy probability — "99.99% spam" may be right only ~90% of the time. Recalibrate (Platt/isotonic) if calibrated probabilities matter.
- **Gaussian NB assumes per-class normality** — violated by skewed, bounded, or multimodal features.
- **No feature interactions, ever.** If the truth is "high income AND low expenses" (neither alone predictive), no amount of data lets plain NB learn it — excluded by structure.
- **Continuous features need a distributional choice or binning** — unlike a decision tree that thresholds raw numbers automatically.
</ConceptBox>

## The Zero-Frequency Problem, Concretely

The most common way a from-scratch NB silently fails. Suppose "cryptocurrency" never appeared in any training ham email:

$$P(\text{"cryptocurrency"} \mid \text{ham}) = \frac{0}{N_{\text{ham}}} = 0$$

Any future legitimate email mentioning it gets the ham score multiplied by this zero, collapsing it regardless of every other ham-like word. The fix (Modules 4–5) is add-$\alpha$ smoothing:

$$P(x_i \mid y) = \frac{N_{y,i} + \alpha}{N_y + \alpha \cdot |\text{values}|}$$

guaranteeing every likelihood is positive, at the cost of slight bias toward uniform. $\alpha=1$ is the conventional default.

## Class Imbalance

Naive Bayes handles imbalance gracefully because the prior $P(y)$ is an explicit, separate term. A rare class's low prior correctly pulls predictions toward the majority *unless* the feature evidence overcomes it — the medical-test behavior from Module 2. This is right when training balance reflects real prevalence, and a liability if the balance was artificially altered (e.g. oversampled) without adjusting the prior.

## Practice

#### Problem 1: Diagnosing Overconfidence
A Gaussian NB spam filter reports `predict_proba` almost always `>0.999` or `<0.001`, even on ambiguous emails. Cause? Is the *label* necessarily wrong?

**Solution:** Likely the independence assumption combining correlated features (length, punctuation, word features are all correlated) — each restates evidence earlier features already gave, driving scores to the extremes. The *label* isn't necessarily wrong (ranking can survive); it's a calibration problem, not automatically an accuracy problem, and shouldn't be trusted as a real probability without recalibration.

#### Problem 2: Smoothing a New Word
A monthly-retrained filter sees a new slang word 10× in spam, 0× in ham. Without smoothing, what happens next month if it appears in one legit email — and how does Laplace change it?

**Solution:** Unsmoothed, $P(\text{word}\mid\text{ham}) = 0$, so any email with it scores ham = 0 — guaranteed spam regardless of other words. With $\alpha=1$, $P(\text{word}\mid\text{ham}) = (0+1)/(N_{\text{ham}} + \alpha|\text{vocab}|)$ — small but positive — so the single word can no longer override all other evidence; ham can still win.
