## From Bayes' Theorem to a Classifier

Substitute a class $y$ for $A$ and a feature vector $\mathbf{x} = (x_1,\ldots,x_n)$ for $B$:

$$P(y \mid \mathbf{x}) = \frac{P(\mathbf{x} \mid y)\, P(y)}{P(\mathbf{x})}, \qquad \hat{y} = \arg\max_{y} \frac{P(\mathbf{x}\mid y)\,P(y)}{P(\mathbf{x})}$$

<ConceptBox title="Drop the denominator">
$P(\mathbf{x})$ doesn't depend on $y$ — it rescales every class's score by the same constant, so it can't change the arg-max:
$$\hat{y} = \arg\max_{y} \; P(\mathbf{x}\mid y)\, P(y)$$
You never need $P(\mathbf{x})$ to classify — only to report calibrated probabilities.
</ConceptBox>

## The Problem: $P(\mathbf{x} \mid y)$ Is Intractable

$P(\mathbf{x}\mid y)$ is a joint over all $n$ features. With binary features that's $2^n$ entries per class — over a million parameters for $n=20$, most feature combinations never seen in training. Direct estimation is impossible.

## The Naive Assumption

Break the joint apart: **features are conditionally independent given the class**.

$$P(\mathbf{x} \mid y) = \prod_{i=1}^{n} P(x_i \mid y)$$

This is *not* unconditional independence. "free" and "money" are correlated across all emails — but the assumption only claims that *once you know an email is spam*, seeing "free" tells you nothing extra about "money". Usually false — hence "naive". The payoff is enormous: instead of one $2^n$ table per class, you estimate $n$ small one-dimensional distributions $P(x_i \mid y)$. Linear, not exponential.

<ConceptBox title="Why 'naive' still classifies well">
Classification needs only the *ranking* of $P(y\mid\mathbf{x})$ across classes to be right, not the exact values. Correlated features often distort every class's score in the same direction, leaving the ranking — and thus the label — intact. Naive Bayes can even be Bayes-optimal when independence is badly violated.
</ConceptBox>

## The Decision Rule

$$\hat{y} = \arg\max_{y} \; P(y) \prod_{i=1}^{n} P(x_i \mid y)$$

Three ingredients, all from counting: the **prior** $P(y)$ (fraction of training rows in class $y$), the **per-feature likelihoods** $P(x_i \mid y)$ (shape covered in Module 5), and the **arg-max** over classes.

## Worked Example: "Play Tennis"

10 days, features Outlook and Windy, label Play:

| Outlook | Windy | Play |
|---|---|---|
| Sunny | False | No |
| Sunny | True | No |
| Overcast | False | Yes |
| Rain | False | Yes |
| Rain | False | Yes |
| Rain | True | No |
| Overcast | True | Yes |
| Sunny | False | Yes |
| Sunny | True | Yes |
| Rain | False | Yes |

Query: Outlook = Sunny, Windy = True.

<DerivationSteps>
<DerivationStep number={1} title="Priors">
7 of 10 Yes, 3 of 10 No: $P(\text{Yes}) = 0.7$, $P(\text{No}) = 0.3$.
</DerivationStep>
<DerivationStep number={2} title="Likelihoods within each class">
Yes days (7): Sunny ×2, True ×2 → both $\tfrac{2}{7} \approx 0.286$. No days (3): Sunny ×2, True ×2 → both $\tfrac{2}{3} \approx 0.667$.
</DerivationStep>
<DerivationStep number={3} title="Prior × likelihoods">
$$\text{score}(\text{Yes}) = 0.7 \times 0.286 \times 0.286 \approx 0.0571$$
$$\text{score}(\text{No}) = 0.3 \times 0.667 \times 0.667 \approx 0.1333$$
</DerivationStep>
<DerivationStep number={4} title="Normalize and pick">
$$P(\text{Yes}\mid\mathbf{x}) \approx 0.30, \qquad P(\text{No}\mid\mathbf{x}) \approx 0.70$$
Predict **No** — even though Yes is the 70% majority. Sunny and Windy are both disproportionately common on No-days, strong enough to overturn the prior.
</DerivationStep>
</DerivationSteps>

## Practice

#### Problem 1: New Query
Classify Outlook = Overcast, Windy = False.

**Solution:** $P(\text{Overcast}\mid\text{Yes}) = 2/7 \approx 0.286$, $P(\text{False}\mid\text{Yes}) = 5/7 \approx 0.714$; $P(\text{Overcast}\mid\text{No}) = 0/3 = 0$, $P(\text{False}\mid\text{No}) = 1/3$. Scores: Yes $= 0.7 \times 0.286 \times 0.714 \approx 0.143$; No $= 0.3 \times 0 \times 0.333 = 0$. Predict **Yes** with total confidence — Overcast's zero count drives the No score to exactly zero. (This brittleness is fixed in Module 7.)

#### Problem 2: Effect of the Assumption
If Sunny and Windy were perfectly correlated but the classifier still multiplies their likelihoods, what happens to the score?

**Solution:** The true joint $P(\text{Sunny},\text{Windy}\mid y)$ would equal $P(\text{Sunny}\mid y)$ alone (windiness adds nothing). Naive Bayes instead computes $P(\text{Sunny}\mid y)\times P(\text{Windy}\mid y)$ — squaring a probability that should appear once, shrinking every class's score. Since the shrinkage is similar across classes the arg-max often survives, but the posteriors become overconfident and poorly calibrated.
