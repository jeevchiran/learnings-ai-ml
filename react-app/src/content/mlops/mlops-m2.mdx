**Learning outcome:** read and run a small TaskFlow pipeline with a validation step and a model-quality gate.

## Tasks, runs, and dependencies

A **task** is one unit of work. A **DAG run** executes the workflow for one trigger or scheduled interval. A **task instance** is a particular task within a run. A worker executes task code; the scheduler arranges eligible work.

Our dependency chain is `extract → validate → train → evaluate → release_candidate`. Under the default success rule, a failed validation prevents downstream training. The release task receives an evaluation report, so it cannot run ahead of evaluation.

## Optional lab: a complete teaching DAG

Use an isolated **Airflow 3** environment with a Python version supported by your selected Airflow release. On Windows, run Airflow through WSL2 or a Linux container. Follow the [official installation instructions](https://airflow.apache.org/docs/apache-airflow/stable/installation/index.html), including the release's constraints file. Do not add Airflow to the website's JavaScript dependencies.

Save the following as `duration_training.py` in that environment's configured DAG folder. The tiny dataset travels through XCom, Airflow's task-message mechanism. This is suitable for this small lab; a real dataset belongs in shared storage.

```python
from datetime import timedelta
import pendulum
from airflow.sdk import dag, task


@dag(
    dag_id="duration_training",
    schedule="@daily",
    start_date=pendulum.datetime(2026, 9, 1, tz="UTC"),
    catchup=False,
    max_active_runs=1,
    default_args={"retries": 2, "retry_delay": timedelta(minutes=1)},
    tags=["mlops-learning"],
)
def duration_training():
    @task
    def extract():
        # Synthetic durations in minutes, already split for this lab.
        return {"train": [8, 10, 12], "validation": [9, 11]}

    @task
    def validate(data):
        for split in ("train", "validation"):
            if not data[split] or any(value <= 0 for value in data[split]):
                raise ValueError("Durations must be positive and nonempty")
        return data

    @task
    def train(data):
        return {"constant_minutes": sum(data["train"]) / len(data["train"])}

    @task
    def evaluate(model, data):
        prediction = model["constant_minutes"]
        mae = sum(abs(y - prediction) for y in data["validation"]) / len(data["validation"])
        return {"mae_minutes": mae, "candidate": model}

    @task
    def release_candidate(report):
        if report["mae_minutes"] > 2.0:
            raise ValueError("Candidate failed the teaching quality gate")
        # Demonstration only: no model registry or endpoint is changed.
        print({"eligible_for_review": True, **report})

    data = validate(extract())
    model = train(data)
    release_candidate(evaluate(model, data))


training_dag = duration_training()

if __name__ == "__main__":
    training_dag.test()
```

The decorated function calls build dependencies when Airflow reads the file. Workers execute their bodies later. The final call creates the DAG object that Airflow discovers. Airflow 2 uses `from airflow.decorators import dag, task`; check the Composer image's Airflow version before adapting this example.

## Run and inspect

In the configured Airflow environment, run `python duration_training.py` for the local DAG test, or trigger `duration_training` in the Airflow UI. A local test needs the environment's Airflow configuration and metadata database initialized. Inspect import errors if the DAG does not appear, then open task logs and the graph.

Expected result: the model predicts 10 minutes, the absolute validation errors are 1 and 1, and MAE is 1.0. All five tasks succeed, and the release log contains `eligible_for_review: True`. This is a constant baseline, not a useful production taxi model.
