## The loss: predict the next token, everywhere at once

  prompt={"Module 3's diagram labelled the decoder input \"Outputs (shifted right)\". A transformer decoder predicts a token at every position in parallel during training. What is position 4's prediction compared against?"}

$$\mathcal{L} = -\frac{1}{T}\sum_{t=1}^{T} \log p(x_{t+1} \mid x_1, \ldots, x_t)$$

Feed the model the target sequence shifted right by one position (the `<sos>`-then-tokens input Module 2 of the previous track already used), and every output position is trained simultaneously to predict the *next* real token — position $t$'s output is graded against $x_{t+1}$. Because the causal mask already prevents position $t$ from seeing $x_{t+1}$ or anything later, this parallel training is completely legitimate: nothing peeks at the answer.

</PredictReveal>

## Teacher forcing, unchanged from before

<PredictReveal
  prompt="At inference time, there's no ground-truth next token to feed in. Does a transformer decoder handle this any differently than the RNN decoder from the previous track did?"
  options={["Yes, transformers use a completely different inference procedure", "No — same autoregressive loop: feed the predicted token back in as the next input"]}
  correct={1}
>

```python
def train_step(model, src, tgt, optimizer, criterion):
    optimizer.zero_grad()
    decoder_input = tgt[:, :-1]     # shifted right: everything except the last token
    decoder_target = tgt[:, 1:]      # everything except the first (<sos>) token
    logits = model(src, decoder_input)                     # (batch, seq_len, vocab_size)
    loss = criterion(logits.reshape(-1, logits.size(-1)), decoder_target.reshape(-1))
    loss.backward()
    optimizer.step()
    return loss.item()
```

Training feeds the entire ground-truth sequence in at once (teacher forcing, same as the previous track's Module 4), computing every position's loss in a single forward pass — the parallelism advantage. Inference still has to generate one token at a time, feeding each prediction back in, because there is no ground truth to shift and feed all at once.

</PredictReveal>

Inference has no ground truth — each token must be generated before it can be fed back in as input for the next position, so generation is inherently sequential even though the model architecture itself is parallel." },

## Gradients flow through Q, K, and V like any other weights

Nothing about attention is special from backpropagation's point of view. $W_Q$, $W_K$, $W_V$, the output projection, and every feed-forward weight are all ordinary parameters sitting in one computational graph; the single cross-entropy loss above is backpropagated through all of them at once, through the softmax, through the masked scores, all the way back to the embedding table.

<ConceptBox title="One training detail specific to transformers">
The original transformer paper uses a **learning-rate warmup**: the learning rate rises linearly for the first few thousand steps, then decays. Very deep, very wide attention stacks are unstable early in training if the learning rate starts high — warmup lets the Query/Key/Value projections settle into a reasonable range before training pushes them hard.
</ConceptBox>

---

<ConceptBox title="TL;DR">
- The loss is ordinary cross-entropy on next-token prediction, computed at every position simultaneously and averaged.
- The causal mask is what makes parallel training legitimate — no position's prediction is graded using information it could see.
- Teacher forcing works exactly as it did with the RNN decoder: feed the shifted ground truth during training, feed generated tokens back in one at a time during inference.
- $W_Q, W_K, W_V$ and every other weight receive gradients through one ordinary backward pass — attention has no special-cased training procedure.
</ConceptBox>
