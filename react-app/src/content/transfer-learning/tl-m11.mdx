# Module 11: The Dice Coefficient and Segmentation Losses

<ConceptBox title="TL;DR">
- **Dice** $= \dfrac{2|A \cap B|}{|A| + |B|}$ — the F1 score of the pixels, and the standard segmentation metric.
- Dice and IoU rank identically: $D = \dfrac{2J}{1+J}$. Dice always reads **higher**, so never compare one against the other.
- **Pixel accuracy is a trap.** With 4% foreground, predicting all background scores 96%.
- Cross-entropy averages over pixels and is dominated by the majority class; **Dice is a set overlap with no background term**, so an empty mask scores 0 however large the image.
- Ship **`BCE + (1 − soft Dice)`**: cross-entropy gives stable per-pixel gradients early, Dice supplies the shape objective that stops the collapse.
</ConceptBox>

<Bridge>
Module 10 built the network. This module decides what "good" means for its output — and the answer is not the accuracy you would use for classification, because segmentation is almost always a severely imbalanced problem.
</Bridge>

## Dice, and its relationship to IoU

$$\text{Dice}(A,B) = \frac{2|A \cap B|}{|A| + |B|} = \frac{2\text{TP}}{2\text{TP} + \text{FP} + \text{FN}}$$

Written the second way it is exactly the **F1 score** computed over pixels — the harmonic mean of precision and recall.

<DiceWidget />

$$\text{IoU} = \frac{|A \cap B|}{|A \cup B|} = \frac{\text{TP}}{\text{TP} + \text{FP} + \text{FN}}$$

The only difference is that Dice counts the intersection **twice** — once in each mask's area. So:

$$D = \frac{2J}{1 + J}, \qquad J = \frac{D}{2 - D}$$

| IoU | Dice |
|---|---|
| 0.50 | 0.667 |
| 0.75 | 0.857 |
| 0.85 | 0.919 |
| 0.90 | 0.947 |

They are **monotone in each other**, so they always rank models the same way. The practical consequence is only that a paper reporting "Dice 0.92" and one reporting "IoU 0.92" are not comparable — the second is much better.

## Why accuracy fails and Dice does not

<SegLossWidget />

Segmentation classes are usually wildly imbalanced: a tumour is a few percent of a scan, a crack is a fraction of a percent of a road image. Two consequences:

- **Pixel accuracy** rewards predicting background. At 4% foreground the empty mask scores 96%.
- **Cross-entropy** averages the per-pixel loss, so the majority class dominates the gradient, and early in training the cheapest way to lower it is to predict nothing.

Dice has **no background term at all**. An empty prediction has zero intersection, so Dice is 0 regardless of how much background it got right.

## Soft Dice — making it differentiable

Hard Dice needs a threshold, and thresholding has zero gradient. The fix is to leave the predictions as probabilities:

$$\mathcal{L}_{\text{Dice}} = 1 - \frac{2\sum_i p_i g_i + \epsilon}{\sum_i p_i + \sum_i g_i + \epsilon}$$

with $p_i \in [0,1]$ the sigmoid output and $g_i \in \{0,1\}$ the label. The $\epsilon$ is not cosmetic — see the derivation.

```python
import torch, torch.nn as nn, torch.nn.functional as F

def soft_dice_loss(logits, targets, eps=1.0):
    """logits: (N,1,H,W) raw; targets: (N,1,H,W) in {0,1}."""
    probs = torch.sigmoid(logits)
    dims = (1, 2, 3)                                   # per-image, then averaged
    inter = (probs * targets).sum(dims)
    denom = probs.sum(dims) + targets.sum(dims)
    dice  = (2 * inter + eps) / (denom + eps)
    return 1 - dice.mean()

class BCEDiceLoss(nn.Module):
    """The default. BCE stabilises early training; Dice fixes the imbalance."""
    def __init__(self, w_bce=0.5, pos_weight=None):
        super().__init__()
        self.w = w_bce
        self.bce = nn.BCEWithLogitsLoss(pos_weight=pos_weight)

    def forward(self, logits, targets):
        return self.w * self.bce(logits, targets) + (1 - self.w) * soft_dice_loss(logits, targets)
```

<ConceptBox title="Reduce per image, then average — not over the whole batch">
Summing the intersection across the entire batch lets a large object in one image compensate for a missed small object in another: the batch-level Dice barely moves, so the network is never punished for the miss.

Computing Dice **per image** and averaging makes every image count equally, which is what you want when object size varies. The `dims=(1,2,3)` above does exactly that. For multi-class, reduce per class as well and average — that is macro-Dice, and it is the number that exposes a class the model is quietly ignoring.
</ConceptBox>

## The alternatives, and when they matter

| Loss | Fixes | Cost |
|---|---|---|
| **BCE** | well-behaved gradients everywhere | collapses under imbalance |
| **Weighted BCE** (`pos_weight`) | imbalance, cheaply | one more hyperparameter to tune |
| **Focal** | down-weights easy pixels continuously | two hyperparameters ($\alpha$, $\gamma$) |
| **Soft Dice** | imbalance, directly optimises the metric | unstable when the target is empty |
| **Tversky** | lets you trade FP against FN ($\alpha$, $\beta$) | tuning |
| **BCE + Dice** | both, in practice | none worth mentioning — this is the default |

**Boundary-aware** losses (Hausdorff, boundary loss) exist for the case where the mask is nearly right but the edge placement is what matters clinically. Reach for them only after BCE+Dice has plateaued.

<DerivationSteps>
<DerivationStep number={1} title="Deriving D = 2J / (1 + J)">

Write both in terms of intersection $I$ and the two areas:

$$D = \frac{2I}{|A| + |B|}, \qquad J = \frac{I}{|A| + |B| - I}$$

Let $S = |A| + |B|$. Then $J = \dfrac{I}{S - I}$, so $J(S - I) = I$, giving $JS = I(1 + J)$ and

$$I = \frac{JS}{1+J}$$

Substitute into Dice:

$$D = \frac{2I}{S} = \frac{2}{S}\cdot\frac{JS}{1+J} = \frac{2J}{1+J} \qquad \blacksquare$$

Since $\frac{dD}{dJ} = \frac{2}{(1+J)^2} > 0$, the map is strictly increasing — Dice and IoU can never disagree about which of two predictions is better.

</DerivationStep>

<DerivationStep number={2} title="What the epsilon actually protects against">

Consider an image whose ground truth is **empty** ($\sum g_i = 0$) and a model that correctly predicts nothing ($\sum p_i \approx 0$). Without $\epsilon$:

$$\mathcal{L} = 1 - \frac{2 \cdot 0}{0 + 0} = 1 - \frac{0}{0}$$

Undefined — in practice `nan`, which propagates through the whole batch and destroys the run. With $\epsilon = 1$:

$$\mathcal{L} = 1 - \frac{0 + 1}{0 + 0 + 1} = 1 - 1 = 0$$

A perfect score for a correct empty prediction, which is the right answer.

The $\epsilon$ also **smooths the gradient** for small objects. With a 20-pixel target, the denominator is tiny and Dice swings violently for a one-pixel change; adding 1 damps that. This is why empty-mask images in a dataset are a real hazard for pure Dice training and why BCE in the mix helps — BCE is perfectly well-behaved on an empty target.

</DerivationStep>
</DerivationSteps>
