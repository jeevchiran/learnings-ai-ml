# Module 6: Encoder–Decoder Architecture

<ConceptBox title="TL;DR">
- An **encoder** compresses input to a compact representation; a **decoder** expands it back to a structured output. The pair is the standard shape for any task whose output is not a single label.
- The **bottleneck** is the point of the design *and* its cost: it forces the network to keep only what matters, and permanently discards everything else.
- For **classification** that loss is fine — you wanted a summary. For **segmentation** it is fatal, because you need a decision at every original pixel.
- Semantic information survives the bottleneck; **precise spatial information does not**. That asymmetry is the entire motivation for skip connections.
- Same skeleton, different jobs: autoencoders, seq2seq, VAEs, and every segmentation network.
</ConceptBox>

<Bridge>
Modules 1–5 used a backbone to produce a *vector*: one embedding per image, position thrown away by global pooling. Segmentation needs the opposite — a label for every pixel, position preserved exactly. This module introduces the architecture that gets from one to the other, and diagnoses the flaw that U-Net exists to fix.
</Bridge>

## The shape

$$\text{input} \xrightarrow{\;\text{encoder}\;} \mathbf{z} \xrightarrow{\;\text{decoder}\;} \text{output}$$

The encoder is the CNN you already know — convolutions interleaved with downsampling, spatial size shrinking while channel count grows. The decoder runs it backwards: upsampling interleaved with convolutions, spatial size growing while channels shrink.

| Task | Encoder input | Bottleneck | Decoder output |
|---|---|---|---|
| Classification | image | feature vector | class scores *(no decoder)* |
| Autoencoder | image | latent code | the same image |
| Denoising AE | noisy image | latent code | clean image |
| **Segmentation** | image | feature map | **per-pixel class map** |
| seq2seq translation | sentence | context vector | sentence |

## The information argument

A $128 \times 128 \times 3$ image is 49,152 numbers. Squeeze it to a 128-dim latent and you have kept **0.26%** of the values. The decoder is not "reconstructing" — it is *generating a plausible image consistent with a summary*.

That works because natural images are enormously redundant: neighbouring pixels correlate, textures repeat, and the space of realistic images is a thin manifold inside $\mathbb{R}^{49152}$. The encoder learns coordinates on that manifold.

But note precisely **what** survives:

- "there is a cat, upper-left, on grass" — survives easily, it is a few numbers
- "the boundary between fur and grass passes exactly through pixel (63, 41)" — does not survive, it is thousands of numbers

<ConceptBox title="Why downsampling is not optional">
It would be tempting to avoid the whole problem: never downsample, keep everything at full resolution. Two things stop you.

**Compute.** A conv layer's cost is proportional to $H \times W \times C_{in} \times C_{out} \times k^2$. Halving $H$ and $W$ quarters the cost, which is what pays for doubling the channels.

**Receptive field.** A stack of 3×3 convs at full resolution grows its receptive field by 2 pixels per layer. To see 200 pixels of context you would need 100 layers. Each stride-2 downsample *doubles* the rate of growth, so five of them get you there in a dozen layers.

You downsample because you need context. You lose spatial precision because you downsampled. Skip connections let you have both, which is Module 9.
</ConceptBox>

## The naive decoder, and why its output is blurry

```python
import torch.nn as nn

class PlainEncoderDecoder(nn.Module):
    """No skips. Trains fine, produces soft, rounded masks."""
    def __init__(self, in_ch=3, classes=2, base=32):
        super().__init__()
        self.enc = nn.Sequential(
            nn.Conv2d(in_ch, base, 3, padding=1), nn.ReLU(),
            nn.MaxPool2d(2),                                   # 1/2
            nn.Conv2d(base, base*2, 3, padding=1), nn.ReLU(),
            nn.MaxPool2d(2),                                   # 1/4
            nn.Conv2d(base*2, base*4, 3, padding=1), nn.ReLU(),
            nn.MaxPool2d(2),                                   # 1/8
        )
        self.dec = nn.Sequential(
            nn.ConvTranspose2d(base*4, base*2, 2, stride=2), nn.ReLU(),   # 1/4
            nn.ConvTranspose2d(base*2, base,   2, stride=2), nn.ReLU(),   # 1/2
            nn.ConvTranspose2d(base,   base,   2, stride=2), nn.ReLU(),   # 1/1
            nn.Conv2d(base, classes, 1),
        )

    def forward(self, x):
        return self.dec(self.enc(x))
```

Three max-pools mean the bottleneck sees the image at $\tfrac{1}{8}$ resolution. Every boundary is now located to within **8 pixels**, and no decoder can recover a precision that no longer exists in its input. The output will be recognisably correct and visibly soft — round corners, thick edges, small objects missing entirely.

## Worked example — how much position is left

Input $256 \times 256$, four stride-2 stages:

$$256 \to 128 \to 64 \to 32 \to 16$$

The bottleneck is $16 \times 16$, so each of its cells covers a $16 \times 16$ patch of the original:

$$\frac{256^2}{16^2} = 256 \text{ pixels per bottleneck cell}$$

Upsampling back to $256^2$ cannot distinguish those 256 pixels — whatever the decoder outputs for one of them, it outputs for a whole neighbourhood, modulated only by what the upsampling interpolates. **Boundary error is bounded below by the downsampling factor**, and that bound is architectural, not a training problem.
