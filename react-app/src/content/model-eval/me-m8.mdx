## The Trap

Filter, wrapper, and embedded methods all pick features by *looking at data*. If that step looks at *too much* data, everything you measure afterward becomes dishonest.

The core leak: if you select features — by **any** method — on the **full** dataset, including rows that later become CV validation folds or the test set, you've let information about those "held-out" rows influence which features were chosen. The CV or test score you then compute isn't honest — you're evaluating a pipeline that got a preview of the answers, because its features were cherry-picked having seen them.

Same category as fitting a `StandardScaler` on the full dataset before splitting — but feature-selection leaks are often larger and easier to miss, because "which features to use" feels like a one-time prep decision rather than part of the model-fitting loop.

## Signal in Pure Noise

Generate 1,000 random features with **zero** true relationship to a random binary target. Honest accuracy of any model here is 50%. Now run this leaky procedure:

1. Correlate each of the 1,000 features with the target, using **all** the data.
2. Keep the top 20 by absolute correlation.
3. Run 5-fold CV on those 20 features.

The reported CV accuracy comes back well above 50% — often 65–75%.

**Why.** With 1,000 independent random features, chance guarantees *some* correlate with the target by luck (multiple-comparisons inflation). Step 2 keeps exactly those. But the correlations in step 1 used **all** the data, including rows that become validation folds — so each of the 20 was chosen partly *because* it correlated with the target within those very folds. Of course it looks predictive there: the folds' targets helped select it. The CV score measures how well the model recognizes patterns it was implicitly shown during selection, not generalization.

```python
import numpy as np
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(42)
X_noise = rng.normal(size=(500, 1000))       # 1000 pure-noise features
y = rng.integers(0, 2, size=500)              # random binary target

# --- LEAKY: select on full data, then CV ---
correlations = np.array([abs(np.corrcoef(X_noise[:, j], y)[0, 1]) for j in range(1000)])
top_20 = np.argsort(correlations)[-20:]
scores = cross_val_score(LogisticRegression(), X_noise[:, top_20], y, cv=StratifiedKFold(5))
print(scores.mean())   # inflated — often well above 0.50 despite pure noise
```

## The Fix: Selection Inside the Pipeline

Make selection part of the model-fitting procedure so it only ever sees the current training data — never the held-out fold. `Pipeline` bundles scaler, selector, and model into one `fit`/`predict` object; `cross_val_score` refits the **entire pipeline** on each training fold.

```python
from sklearn.pipeline import Pipeline
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import cross_val_score, StratifiedKFold

# --- CORRECT: selection lives inside the pipeline ---
pipe = Pipeline([
    ('scale', StandardScaler()),
    ('select', SelectKBest(score_func=f_classif, k=20)),
    ('clf', LogisticRegression()),
])
scores = cross_val_score(pipe, X_noise, y, cv=StratifiedKFold(5))
print(scores.mean())   # honest — back near 0.50, as it should be for pure noise
```

On each fold, `SelectKBest` picks its top 20 using only that fold's *training* rows; the validation rows stay untouched until scoring. On pure noise, the score correctly hovers at chance — the "best 20" chosen per training fold have no reason to look good on that fold's held-out rows.

## Nested CV: When You're Also Tuning

A subtler, milder leak: if you use `GridSearchCV` to search `k` (or a regularization strength) using the *same* CV loop you report as your final score, you picked those hyperparameters *because* they scored well on those exact folds — so reporting that score is optimistic. Configs that fit the noise in those folds are favored, and that favoritism won't repeat on new data.

**Nested CV** uses two loops:

- **Inner** — selects hyperparameters (or `k`); where `GridSearchCV` tunes.
- **Outer** — never used for any decision; only scores whatever the inner loop chose, on data it never optimized against.

```python
from sklearn.model_selection import GridSearchCV, cross_val_score, StratifiedKFold

pipe = Pipeline([('scale', StandardScaler()), ('select', SelectKBest(score_func=f_classif)), ('clf', LogisticRegression())])
param_grid = {'select__k': [5, 10, 20, 50], 'clf__C': [0.01, 0.1, 1, 10]}

grid_search = GridSearchCV(pipe, param_grid, cv=StratifiedKFold(3), scoring='accuracy')  # inner
nested_scores = cross_val_score(grid_search, X_noise, y, cv=StratifiedKFold(5))           # outer
print(nested_scores.mean())   # honest, accounting for tuning-selection leak too
```

Each outer fold trains a fresh `GridSearchCV` — the inner search runs entirely within that outer fold's training rows, then gets scored on its held-out rows. Expensive: 5 outer × 3 inner × 16 grid = 240 fits vs. 16 for plain grid search. The price of a truly unbiased estimate — nested CV is the gold standard for a number you can fully trust; plain CV-after-tuning is a reasonable cheaper approximation for comparing configs.

## Practice

#### Problem 1: Spot the Leak

```python
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

selector = SelectKBest(f_classif, k=15)
X_selected = selector.fit(X, y).transform(X)   # fit on ALL of X, y

scores = cross_val_score(LogisticRegression(), X_selected, y, cv=5)
print(scores.mean())
```

Where's the leak, and the fix?

**Solution:** The `selector.fit(X, y)` line fits `SelectKBest` on the entire dataset before `cross_val_score` splits it — so the 15 features were chosen having seen every row, including future validation folds. Optimistic, like the pure-noise case. Fix: never `.fit()` the selector outside the CV loop. Wrap it: `Pipeline([('select', SelectKBest(f_classif, k=15)), ('clf', LogisticRegression())])` and pass *that* (not pre-selected `X_selected`) to `cross_val_score(pipe, X, y, cv=5)`. Selection then refits per training fold, validation stays unseen until scoring.
