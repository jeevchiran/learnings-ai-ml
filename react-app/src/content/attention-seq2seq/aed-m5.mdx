# Module 5: The Limitation of Encoder-Decoder — the Bottleneck

<Bridge>

</Bridge>

## One vector, however long the sentence

<PredictReveal
  prompt='"I love coffee" (3 tokens) and a 40-word paragraph both get compressed into the same fixed-size context vector — say, 512 numbers. Does the 40-word sentence get more room in that vector, or the same room?'
  options={["More room — longer inputs get a proportionally larger context vector", "The same room — the vector's size never changes"]}
  correct={1}
>

<BottleneckWidget />

The context vector $c$ has a fixed dimensionality, set once when the model is built — say, 512 numbers, whether the source sentence is three words or three hundred. Every word of a long sentence has to be squeezed into that same 512-number budget. Cho et al. (2014) and Bahdanau et al. (2014) both measured this directly: translation quality (BLEU) for a vanilla encoder-decoder degrades sharply as source sentence length increases, while a human translator's quality doesn't.

</PredictReveal>

  { q: "Why does the encoder-decoder's translation quality degrade on long sentences specifically?", a: "Because the context vector's size is fixed regardless of input length, so a longer sentence has to be compressed into the same amount of representational space as a short one. Past some length, the compression starts discarding information the decoder actually needs." },
]} />

## What gets lost first

<PredictReveal
  prompt='The encoder reads the source sentence left to right, updating one hidden state as it goes. In a long sentence, is information from the FIRST word or the LAST word more likely to survive intact into the final context vector?'
  options={["The first word — it's had the most updates applied on top of it", "The last word — it's freshest, closest to the final hidden state"]}
  correct={1}
>

Because the encoder's hidden state is repeatedly overwritten step by step, information from early tokens has to survive being folded through every subsequent update. In a long sentence, the final hidden state is dominated by whatever was read most recently — early words are the first casualties of the compression. This is the same **vanishing-influence** pattern the RNN track covered for gradients (Module 9 there), now showing up as a *representation* problem instead of a *training* one.

This is architectural, not a training bug: no amount of extra training data or a bigger hidden size fully fixes it, because the bottleneck is structural — one vector has to represent an unboundedly long sequence.

</PredictReveal>

<Recall items={[
  { q: "Is the bottleneck problem fixable by training longer or using a bigger hidden state?", a: "Not fully. ---

<ConceptBox title="TL;DR">
- The context vector's dimensionality is **fixed**, regardless of source sentence length — long sentences and short sentences get the same representational budget.
- Cho et al. (2014) and Bahdanau et al. (2014) both measured translation quality degrading sharply as source length grows, for exactly this reason.
- Because the hidden state is repeatedly overwritten while reading, **early tokens** are diluted the most by the time the final context vector is formed.
- This is a structural limitation of the architecture, not a training bug — bigger hidden sizes or more data raise the ceiling but don't remove it.
</ConceptBox>
