## The four steps, once per decoder step

<PredictReveal
  prompt={"Before the decoder can decide how much to attend to each source word, it needs some notion of \"what am I trying to generate right now\". Does the score computation happen before or after the decoder's own hidden state for this step is available?"}
  options={["Before — scores are computed first, hidden state comes after", "After — the decoder's current hidden state is an input to the score computation"]}
  correct={1}
>

Every decoder step $i$ runs the same four-stage pipeline:

1. **Score.** Compare the decoder's *previous* hidden state $s_{i-1}$ against every encoder hidden state $h_j$, producing one raw score $e_{ij}$ per source token. The decoder's own state has to exist first — the scores measure how relevant each source token is *given what the decoder is about to generate next*.
2. **Normalize.** Pass the scores through softmax across $j$, turning them into attention weights $\alpha_{ij}$ that are non-negative and sum to 1 — a proper probability distribution over source positions.
3. **Combine.** Take the weighted sum $c_i = \sum_j \alpha_{ij} h_j$ — the step-specific context vector from Module 6.
4. **Generate.** Feed $c_i$ (usually concatenated with $s_{i-1}$ or the previous output embedding) into the decoder's RNN cell, producing the new hidden state $s_i$ and, from it, the predicted token.

Then the whole thing repeats for step $i+1$, using the freshly updated $s_i$.

## Why softmax, specifically

<PredictReveal
  prompt="Instead of softmax, what would go wrong if the raw scores e_ij were used directly as weights in the weighted sum?"
  options={["Nothing — raw scores work identically well", "The weights wouldn't be guaranteed non-negative or sum to 1, so the 'weighted average' could blow up or go negative"]}
  correct={1}
>

Raw scores $e_{ij}$ can be any real number — negative, huge, tiny. Feeding them directly into the weighted sum would make $c_i$ an uncontrolled linear combination, not an *average*, of the encoder states — nothing would stop it from landing far outside the range the encoder states actually occupy. Softmax fixes both problems at once: it forces every weight to be non-negative and forces the whole set to sum to 1, so $c_i$ is guaranteed to be a genuine weighted average — a point inside the convex hull of the $h_j$'s, never an extrapolation beyond them.

</PredictReveal>

---

<ConceptBox title="TL;DR">
- Every decoder step runs the same four-stage pipeline: **score** each encoder state against the decoder's previous hidden state, **normalize** via softmax, **combine** into a weighted sum, **generate** the next token from it.
- The decoder's previous hidden state $s_{i-1}$ is an *input* to the scoring step — scoring happens with knowledge of what the decoder is about to generate.
- Softmax turns arbitrary raw scores into a proper probability distribution — non-negative, summing to 1 — which is what makes $c_i$ a genuine weighted average rather than an uncontrolled combination.
- The pipeline repeats independently at every decoder step, using that step's own freshly updated hidden state.
</ConceptBox>
