<ConceptBox title="TL;DR">
- A tree is a learned flowchart: each internal node asks $x_j\le t$, each leaf stores an answer (majority class, or the mean for regression).
- Prediction is one root-to-leaf traversal — $O(\text{depth})$, so inference is very fast.
- **A tree with $K$ leaves is a piecewise-constant function over $K$ rectangular regions.** That single sentence explains both its power and its limits.
- Structural win over linear models: XOR is unlearnable by logistic regression and trivial for a depth-2 tree.
- Different samples use different features — a feature can be decisive on one path and never consulted on another.
</ConceptBox>

## Why Decision Trees?

A cardiologist diagnoses by a chain of focused questions: "Over 50?" → "Smoker?" → "BP above 140?" — each narrowing the space until a leaf: *high risk, refer*. That protocol *is* a decision tree encoded in expert reasoning — and it can be drawn as a graph and learned from data.

A linear model can't do this. Logistic regression draws one hyperplane, but many boundaries aren't straight. **XOR**: class 1 when both features are high or both low, class 0 otherwise — not linearly separable. Logistic regression scores ~50%; a depth-2 tree separates it perfectly with two axis-aligned cuts. A structural advantage.

<Bridge>
A tree algorithm formalizes the doctor's protocol: it learns the questions and thresholds from labeled data, picking at each step the split that most cleanly separates classes. The result is interpretable (read it like a flowchart) and precise (a piecewise-constant function over feature space).
</Bridge>

## Anatomy

<ConceptBox title="Key terms">
- **Root** — top node; holds all samples and the first split.
- **Internal node** — a split condition $x_j \leq t$ routing each sample left/right.
- **Leaf** — terminal node; predicts (majority class, or mean for regression).
- **Branch** — edge to a child (left = true, right = false).
- **Depth** — longest root-to-leaf path length (root-only = depth 0).
- **Path** — the nodes a sample traverses; encodes all conditions it satisfied.
</ConceptBox>

Each internal node asks one binary question; every training sample follows a unique root-to-leaf path set by its features. Two samples reaching the same leaf get the same prediction — the tree partitions the feature space.

## Prediction Is Traversal

Given $\mathbf{x}$: start at the root, evaluate the split, follow the matching branch, repeat to a leaf, return its stored value. Classification leaves store the **majority class** (optionally the class-probability vector); regression leaves store the **mean** target. Cost is $O(d)$ — one comparison per level — so inference is very fast.

**Trace (loan tree):** applicant income 60k, credit 680, employed full-time.

Each sample's traversal length equals its leaf's depth, so a tree spends a shallow budget on simple, well-separated regions and deeper subtrees on ambiguous ones.

## The Tree as a Function

A tree with $K$ leaves partitions the input space into $K$ disjoint rectangular regions $R_1,\ldots,R_K$, each with a constant prediction $c_k$:

$$f(\mathbf{x}) = \sum_{k=1}^{K} c_k \cdot \mathbf{1}\bigl[\mathbf{x} \in R_k\bigr]$$

Exactly one indicator is 1 for any input, so the sum collapses to whichever region contains $\mathbf{x}$.

<ConceptBox title="What training does">
Find the partition $\{R_k\}$ and predictions $\{c_k\}$ minimizing a loss — Gini/entropy for classification, MSE for regression. The exact optimum is NP-hard, so CART solves it greedily, one split at a time.
</ConceptBox>

**Axis-aligned cuts.** Every split $x_j \leq t$ is parallel to a feature axis, so regions are axis-aligned hyper-rectangles. Unlike an SVM (oblique) or a net (curved), a tree cuts only horizontally/vertically. Consequently: a diagonal boundary needs many small stairstep cuts; XOR is perfect at depth 2 (its boundary is already axis-aligned); deep trees approximate any smooth boundary but risk overfitting. Rectangles make every leaf a human-readable rule — "income > 50k AND employed = full-time" — which no other mainstream model produces directly.

## Classification vs. Regression Trees

Same structure; only the leaf content and split criterion differ:

| Property | Classification | Regression |
|---|---|---|
| Leaf prediction | Majority class / probabilities | Mean of leaf targets |
| Split criterion | Gini, entropy | MSE / MAE reduction |
| Output | Discrete label | Continuous value |

This module covers classification; regression trees use the same CART with MSE replacing impurity.

## Practice

**Problem 1 — Tracing.** Tree: root temp ≤ 20 → No Rain; else humidity ≤ 60 → No Rain, else Rain.

- (a) temp 15, hum 70: 15 ≤ 20 True → **No Rain** (humidity unused).
- (b) temp 25, hum 50: 25 ≤ 20 False → 50 ≤ 60 True → **No Rain**.
- (c) temp 22, hum 65: False → 65 ≤ 60 False → **Rain**.

**Problem 2 — Piecewise function.** Splits: $x_1 \leq 3$; within left $x_2 \leq 2$; within right $x_2 \leq 5$. Leaves $c_1=1, c_2=0, c_3=1, c_4=0$.

$$f(x_1, x_2) = \mathbf{1}[x_1 \leq 3,\, x_2 \leq 2] + \mathbf{1}[x_1 > 3,\, x_2 \leq 5]$$

**Problem 3 — Regression tree + MSE.** Data $(x,y)$: (1,2.1),(2,2.9),(3,7.2),(4,8.1),(5,7.8).

*Part A* — split $x \leq 2.5$: left mean $= 2.5$, right mean $= 7.7$. For $x=3.5$ → **7.7**.
$$\text{MSE} = \tfrac{1}{5}[0.16 + 0.16 + 0.25 + 0.16 + 0.01] = 0.148$$

*Part B* — add split $x \leq 4.0$ in the right subtree: left 2.5, right-left $(7.2+8.1)/2 = 7.65$, right-right 7.8.
$$\text{MSE} = \tfrac{1}{5}[0.16 + 0.16 + 0.2025 + 0.2025 + 0] = 0.145$$
The right-right leaf perfectly fits its single point — the start of overfitting.
