## The Tuning Mindset

Before turning any knob, ask: am I reducing **bias**, **variance**, or **computation**?

<ConceptBox title="Organizing principle">
- Complexity knobs → the bias-variance tradeoff.
- Randomness knobs → variance.
- Computation knobs → training cost, not fundamental quality.

Underfit (high train + test error) → **reduce bias**, add complexity. Overfit (low train, high test) → **reduce variance** via regularization, sampling, or depth limits.
</ConceptBox>

## Random Forest Hyperparameters

The ensemble (bagging + feature randomness) does the variance reduction, so individual trees grow with little regularization.

| Parameter | Default | Controls | Increase → |
|---|---|---|---|
| `n_estimators` | 100 | ensemble size | more stable, diminishing returns |
| `max_depth` | None | tree complexity | lower bias, higher variance |
| `max_features` | "sqrt" | feature randomness | higher correlation, lower bias |
| `min_samples_leaf` | 1 | leaf size | lower variance, higher bias |
| `bootstrap` | True | OOB + decorrelation | enables OOB estimate |

- **`n_estimators` (B):** in $\text{Var}(F_B) = \rho\sigma^2 + \frac{(1-\rho)\sigma^2}{B}$, more B shrinks the second term; the $\rho\sigma^2$ floor is irreducible — hence diminishing returns past ~100–200 trees. Use OOB error vs B, stop at the elbow.
- **`max_features` (m):** the primary dial for tree correlation $\rho$. Smaller m decorrelates trees (lowers $\rho$) but raises individual bias ($\sigma^2$). Defaults: $\sqrt{p}$ (classification), $p/3$ (regression). **Usually the single most impactful RF knob.**
- **`max_depth`:** grow full trees (`None`) — averaging controls ensemble variance, and limiting depth just adds bias.
- **`min_samples_leaf`:** like kernel smoothing — larger leaves average more points, cutting variance. Try [1, 5, 10, 20]; larger helps noisy data.

## Gradient Boosting Hyperparameters

Far more sensitive than RF — the additive construction compounds overfitting across iterations.

**The critical interaction — `learning_rate` × `n_estimators`.** Total capacity $\approx \eta \cdot M \cdot \bar{h}$: halve $\eta$ from 0.1 to 0.05 and you need roughly double $M$ to fit equally.

<ConceptBox title="Never tune η and M independently">
Their product sets effective capacity. Small $\eta$ without more $M$ underfits; large $\eta$ without fewer $M$ overfits. Always adjust together.
</ConceptBox>

| Parameter | Default | Bias | Variance | Range |
|---|---|---|---|---|
| `n_estimators` (M) | 100 | ↓ | ↑ (no ES) | 100–2000 |
| `learning_rate` (η) | 0.1 | — | ↓ | 0.01–0.3 |
| `max_depth` | 3 | ↓ | ↑ | 2–8 |
| `subsample` | 1.0 | slight ↑ | ↓ | 0.5–1.0 |
| `colsample_bytree` | 1.0 | slight ↑ | ↓ | 0.5–1.0 |
| `min_child_weight` | 1 | ↑ | ↓ | 1–20 |
| `reg_lambda` (λ) | 1 | ↑ | ↓ | 0.1–100 |

- **`max_depth`:** shallow (2–6), unlike RF — shallow trees build complexity gradually; shallower needs more iterations.
- **`subsample`:** the "stochastic" in stochastic GB — a random fraction (no replacement) per tree; sweet spot 0.6–0.8 (below 0.5 is too noisy).
- **XGBoost regularization:** leaf weight $w_j^* = -\frac{\sum_{i \in I_j} g_i}{\sum_{i \in I_j} h_i + \lambda}$. Default $\lambda = 1$ already regularizes; keep $\alpha = 0$ and tune $\lambda$ in [0.1, 1, 10, 100].

## Tuning Recipes

**Random Forest:** (1) baseline `n_estimators=200, max_features='sqrt', max_depth=None, min_samples_leaf=1`, note OOB + test error; (2) plot OOB vs B (10–300), stop at the elbow; (3) grid `max_features` over $[\lfloor\sqrt p/2\rfloor, \lfloor\sqrt p\rfloor, \lfloor2\sqrt p\rfloor]$ (+ $p/3$ for regression) — the highest-impact change; (4) grid `min_samples_leaf` [1, 5, 10, 20] — improvement above 1 signals noisy data.

**Gradient Boosting:** (1) robust defaults `subsample=0.8, colsample_bytree=0.8, max_depth=4, learning_rate=0.1`; (2) find M via early stopping (held-out 15–20%, up to M_max=1000); (3) test budget equivalence — `learning_rate=0.05` with ~2×M*, often generalizes better; (4) grid `max_depth` [2–6] (3–4 usual for tabular); (5) fine-tune `min_child_weight`, `subsample`, `colsample_bytree`, `reg_lambda` last.

## Early Stopping

The most practical anti-overfitting tool for GB: reserve 10–20% as validation, evaluate the ensemble's validation loss after each tree, and stop when it hasn't improved for `early_stopping_rounds` (10–50) — using the model at the best iteration m*, not the last. m* *is* the effective `n_estimators` for that learning rate, so you needn't grid-search it separately.

```python
import xgboost as xgb

model = xgb.XGBClassifier(
    n_estimators=1000,          # max; early stopping halts sooner
    learning_rate=0.05,
    max_depth=4,
    subsample=0.8,
    colsample_bytree=0.8,
    early_stopping_rounds=50,
    eval_metric='logloss',
)
model.fit(X_train, y_train, eval_set=[(X_val, y_val)], verbose=100)
print(f"Best iteration: {model.best_iteration}")
```
