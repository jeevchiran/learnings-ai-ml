<ConceptBox title="TL;DR">
- One rule runs nearly all of training: $\theta_{t+1} = \theta_t - \eta\,\nabla f(\theta_t)$.
- The learning rate $\eta$ sits on a knife's edge — too small wastes steps, too large diverges. The tipping point is set by the curvature.
- Convergence is only *guaranteed* on a convex bowl. Real loss surfaces have local minima, plateaus and saddles.
- Momentum and Adam exist precisely to survive that non-convex reality.

## The Optimization Loop, Distilled

Almost everything you'll train in this curriculum reduces to the same three lines: compute a gradient, step opposite to it, repeat.

<DerivationSteps>
<DerivationStep number={1} title="The update rule">
$$\theta_{t+1} = \theta_t - \eta\,\nabla f(\theta_t)$$
$\theta$ is the parameter vector, $\eta$ is the **learning rate**. The gradient points toward steepest *ascent* (Module 9) — subtracting it steps toward steepest *descent*.
</DerivationStep>
<DerivationStep number={2} title="Why it works on a convex bowl">
For $f(x,y)=ax^2+cy^2$ with $a,c>0$, every step shrinks $f$ as long as $\eta$ is small enough — the gradient always points back toward the minimum, and a small enough step can't overshoot past it.
</DerivationStep>
<DerivationStep number={3} title="Why the learning rate has a knife's edge">
Too small: converges, but wastes steps. Too large: each step overshoots further than the last step undershot — the iterate diverges instead of converging. There's a critical $\eta$ (tied to the curvature, i.e. the Hessian eigenvalues from Module 11) above which this happens.
</DerivationStep>
</DerivationSteps>

<GradientDescentWidget defaultShape="Convex bowl" />

<ConceptBox title="Common confusion — gradient descent isn't guaranteed to find THE minimum">
On a convex bowl, yes — there's only one minimum, and descent finds it. Real loss surfaces (deep nets especially) are not convex: many local minima, saddle points, plateaus. Momentum, adaptive learning rates (Adam), and random restarts all exist to cope with that non-convex reality — plain gradient descent's convergence guarantee only holds on the convex case.
</ConceptBox>

## In Python

```python
import numpy as np

def f(xy):
    x, y = xy
    return x**2 + y**2

def grad(xy, h=1e-5):
    x, y = xy
    dfdx = (f([x + h, y]) - f([x - h, y])) / (2 * h)
    dfdy = (f([x, y + h]) - f([x, y - h])) / (2 * h)
    return np.array([dfdx, dfdy])

theta = np.array([4.0, 3.0])
lr = 0.1
for step in range(40):
    theta = theta - lr * grad(theta)

print(theta, f(theta))   # converges toward [0, 0], f -> 0
```

In practice you never hand-write `grad()` — autodiff (Module 9) computes it, and `torch.optim.SGD`/`Adam` wrap the update rule for you.

## Practice

**Problem 1.** $f(x)=x^2$, start at $x_0=4$, $\eta=0.1$. Compute $x_1$ and $x_2$.

**Solution:** $f'(x)=2x$. $x_1 = 4 - 0.1(8) = 3.2$. $x_2 = 3.2 - 0.1(6.4) = 2.56$ — shrinking geometrically toward 0.

**Problem 2.** Same setup, but $\eta=1.1$. What happens?

**Solution:** $x_1 = 4 - 1.1(8) = -4.8$ — larger in magnitude than the start. Each step overshoots further; the sequence diverges instead of converging, since $|1-2\eta|>1$ for $\eta=1.1$.
