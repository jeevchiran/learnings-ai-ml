# Module 2: Math Operations on Images

<ConceptBox title="TL;DR">
- **Point operations** apply the same scalar function to every pixel independently — no neighbours involved. Cheap, parallel, and the whole of this module.
- `uint8` arithmetic **saturates** in OpenCV (`250 + 10 = 255`) but **wraps** in raw NumPy (`250 + 10 = 4`). This is a real, silent bug source.
- Brightness/contrast is affine: $g = \alpha f + \beta$. Gamma is not: $g = 255(f/255)^\gamma$ — it changes midtones without clipping the ends.
- **Thresholding** turns intensity into a binary mask; masks then drive `bitwise_and` to isolate regions.
- Frame differencing (`absdiff`) is motion detection in one line, and it is still the first thing you try.
</ConceptBox>

<Bridge>

## The operations that matter

**Blending** — a weighted average, used for image compositing and for the Mixup augmentation:

$$g(x,y) = \alpha \cdot f_1(x,y) + (1-\alpha) \cdot f_2(x,y)$$

**Brightness and contrast** — an affine map on intensity:

$$g = \alpha f + \beta \qquad \alpha > 1 \text{ stretches contrast}, \; \beta \text{ shifts brightness}$$

**Gamma** — the non-linear alternative, because $\alpha f + \beta$ clips whatever it pushes past 255:

$$g = 255 \left(\frac{f}{255}\right)^{\gamma}$$

$\gamma < 1$ brightens shadows and leaves highlights alone; $\gamma > 1$ darkens. Gamma is monotone and bounded, so nothing ever clips.

**Thresholding** — the bridge from continuous intensity to a discrete mask:

$$g = \begin{cases} 255 & f > T \\ 0 & \text{otherwise}\end{cases}$$

## Worked example — the saturation trap

A pixel holds 250. Add 10.

```python
import numpy as np, cv2

a = np.uint8([[250]])
b = np.uint8([[10]])

print(a + b)             # [[4]]    ← NumPy wraps modulo 256
print(cv2.add(a, b))     # [[255]]  ← OpenCV saturates
```

$250 + 10 = 260$, and $260 \bmod 256 = 4$. Every bright pixel in your image just became nearly black. Use `cv2.add`, or promote to `int16` before doing the arithmetic and clip afterwards.

```python
# safe manual version
out = np.clip(a.astype(np.int16) + b.astype(np.int16), 0, 255).astype(np.uint8)
```

## Frame differencing — motion in three lines

```python
diff = cv2.absdiff(frame_t, frame_prev)          # per-pixel |difference|
grey = cv2.cvtColor(diff, cv2.COLOR_BGR2GRAY)
_, motion = cv2.threshold(grey, 25, 255, cv2.THRESH_BINARY)
```

The threshold of 25 is doing the real work: it decides what counts as change versus sensor noise. Too low and every frame is "motion"; too high and a slow-moving object disappears. There is no correct value — only a value tuned to your camera and lighting, which is exactly the fragility that pushed detection toward learned models.
