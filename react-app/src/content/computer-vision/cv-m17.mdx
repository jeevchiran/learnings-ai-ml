# Module 17: Training YOLO on Your Own Data

<ConceptBox title="TL;DR">
- The dataset is **a folder convention plus one YAML**. Labels are `class cx cy w h`, all normalised to $[0,1]$, one `.txt` per image.
- The loader finds labels by replacing `/images/` with `/labels/` in the path. Break that and you get a silent all-background dataset.
- **Split by scene, not by frame.** Consecutive video frames in train and val is the most common cause of a beautiful val mAP and a useless model.
- Start from COCO weights, freeze nothing, train `yolov8s` for ~100 epochs. Fine-tuning beats training from scratch by a wide margin on small datasets.
- Read the **confusion matrix and the PR curve**, not the mAP number. mAP tells you *that* it failed, those tell you *where*.
</ConceptBox>

<Bridge>
Module 16 ran a pretrained model. This module replaces its classes with yours, which is 90% data engineering and 10% training — in that ratio, and the modules order the material accordingly.
</Bridge>

## The layout

```
weld-defects/
├── data.yaml
├── images/
│   ├── train/  img_0001.jpg  img_0002.jpg  …
│   └── val/    img_0500.jpg  …
└── labels/
    ├── train/  img_0001.txt  img_0002.txt  …
    └── val/    img_0500.txt  …
```

The paths must mirror exactly: `images/train/img_0001.jpg` ↔ `labels/train/img_0001.txt`. An image with **no** `.txt` is treated as having no objects — a valid, useful background sample, and also exactly what a broken path looks like.

```yaml
# data.yaml
path: ../datasets/weld-defects     # root, relative to the ultralytics settings dir
train: images/train
val:   images/val
names:
  0: crack
  1: rust
  2: dent
```

## The label format

<YoloLabelWidget />

One line per object, five space-separated numbers:

$$\texttt{class\_id} \quad \frac{c_x}{W} \quad \frac{c_y}{H} \quad \frac{w}{W} \quad \frac{h}{H}$$

<ConceptBox title="The four label bugs, in order of frequency">
1. **Pixels instead of fractions.** Values above 1. The loss goes to nonsense immediately; at least this one is visible.
2. **Corner instead of centre.** Every box lands up and to the left of its object. Trains fine, mAP caps at something mediocre, and nothing looks broken.
3. **Class ids off by one.** Someone starts at 1 because that is what COCO JSON does. YOLO is 0-indexed; the last class silently never trains.
4. **Wrong image dimensions in the converter.** Normalising by the *resized* dimensions when the labels were drawn on the original. Boxes are systematically scaled.

All four are caught in thirty seconds by drawing ten random labels back onto their images before you train. Do that. Every time.
</ConceptBox>

## Converting from COCO JSON

```python
import json, os
from pathlib import Path

coco = json.load(open('annotations.json'))
imgs = {im['id']: im for im in coco['images']}
# COCO category ids are arbitrary integers; YOLO needs contiguous 0-based ones
cat2idx = {c['id']: i for i, c in enumerate(sorted(coco['categories'], key=lambda c: c['id']))}

lines = {}
for a in coco['annotations']:
    if a.get('iscrowd'):                       # crowd regions have no usable box
        continue
    im = imgs[a['image_id']]
    W, H = im['width'], im['height']
    x, y, w, h = a['bbox']                     # COCO is xywh, top-left, absolute pixels
    cx, cy = x + w / 2, y + h / 2              # → centre
    lines.setdefault(im['file_name'], []).append(
        f"{cat2idx[a['category_id']]} {cx/W:.6f} {cy/H:.6f} {w/W:.6f} {h/H:.6f}")

Path('labels/train').mkdir(parents=True, exist_ok=True)
for fname, ls in lines.items():
    Path('labels/train', Path(fname).with_suffix('.txt').name).write_text('\n'.join(ls))
```

Three conversions happen in that loop, and each is a bug if skipped: **xywh → cxcywh**, **absolute → normalised**, and **arbitrary category id → contiguous index**.

## Splitting — the part that decides whether your metric is real

Random splitting is wrong whenever samples are correlated. From worst to best:

| Split | Problem |
|---|---|
| Random over video frames | frame 100 in train, frame 101 in val — near-duplicates. Val mAP is meaningless. |
| Random over augmented copies | the same photo appears on both sides |
| Random over photos of the same object | the model memorises that object, not the class |
| **By scene / session / capture day** | ✓ what you want |

If your data came from video, split by **clip**. If it came from a factory, split by **shift or line**. The rule: whatever varies between your training set and deployment should also vary between train and val.

## Training

```python
from ultralytics import YOLO

model = YOLO('yolov8s.pt')        # start from COCO weights, not yolov8s.yaml
model.train(
    data='data.yaml',
    epochs=100,
    imgsz=640,
    batch=16,                     # or batch=-1 for auto-sizing to your GPU
    patience=25,                  # early stop after 25 epochs without improvement
    hsv_h=0.015, hsv_s=0.7, hsv_v=0.4,     # colour jitter (Module 7's domain shift)
    fliplr=0.5, degrees=0.0,      # horizontal flip yes; rotation off — Module 4 explains why
    mosaic=1.0, close_mosaic=10,  # mosaic on, disabled for the final 10 epochs
    project='runs', name='weld_v1',
)

metrics = model.val()
print(metrics.box.map, metrics.box.map50)      # mAP@50-95, mAP@50
```

Two of those defaults are worth understanding:

- **`degrees=0.0`.** Rotation inflates axis-aligned boxes — Module 4 computed a 98% area increase at 30°. Every rotated box then teaches the model that a chunk of background is object. Leave rotation off unless your objects genuinely appear at arbitrary angles.
- **`close_mosaic=10`.** Mosaic stitches four images into one, which is excellent for teaching scale and context but produces boxes clipped at seams. Turning it off for the last epochs lets the model finish on clean, realistic images.

## Reading the results

`runs/weld_v1/` contains more than the number:

| File | What it tells you |
|---|---|
| `results.png` | loss curves. Box loss flat from epoch 1 → your labels are wrong. |
| `confusion_matrix.png` | **which** classes are confused, and how much goes to `background` |
| `PR_curve.png` | per-class AP — the mean is hiding something |
| `val_batch0_pred.jpg` | predictions on real val images, next to the labels |

The `background` column of the confusion matrix is the one to read first. Heavy leakage into it means missed detections (low recall); heavy leakage *from* it means false positives. Those two failures need opposite fixes — more positive examples versus more hard negative backgrounds — and the mAP number alone cannot distinguish them.

## Export

```python
model.export(format='onnx', imgsz=640, simplify=True, opset=12)
# also: 'engine' (TensorRT), 'coreml', 'tflite', 'openvino'
```

Exported graphs usually stop **before** NMS, so you are back to the raw `(1, 84, 8400)` tensor from Module 16 and must reimplement decode + NMS + un-letterbox in the target runtime. Verify by running one image through both paths and comparing boxes — a 1-pixel difference is rounding, a 100-pixel difference is your letterbox maths.
