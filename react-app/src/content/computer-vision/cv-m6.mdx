# Module 6: Regions of Interest

<ConceptBox title="TL;DR">
- An ROI is **an array slice**: `img[y1:y2, x1:x2]`. Row range first. It is a *view*, not a copy — writing to it writes through to the original.
- **Crop** changes the shape; **mask** preserves it and zeroes the outside. Rectangles want crops, irregular shapes want masks.
- Three box formats — `xywh`, `xyxy`, `cxcywh` — and mixing them is the quietest bug in detection, because nothing errors.
- **Contours + connected components** are how you get boxes without a neural network, and they still beat one when the object is a colour blob.
- Every region-based detector in this track (R-CNN through Faster R-CNN) is this module plus a CNN.
</ConceptBox>

<Bridge>
Modules 1–5 processed whole images. Detection needs to talk about *parts* of an image — this module is the vocabulary for that, and the box formats introduced here are used unchanged for the rest of the track.
</Bridge>

## The slice

```python
roi = img[y1:y2, x1:x2]        # (y2-y1, x2-x1) or (…, …, 3)
```

Two things about this line surprise people:

**It is a view.** `roi[:] = 0` blacks out that rectangle *in `img`*. Use `.copy()` when you need independence.

**It is silently clipped.** `img[0:5000, 0:5000]` on a 480×640 image does not raise — you get a 480×640 result. A box that ran off the edge produces a smaller ROI than you asked for, and downstream shape assumptions break far from the cause.

## Box formats

| Format | Fields | Used by |
|---|---|---|
| `xywh` | top-left + size | OpenCV, COCO annotations |
| `xyxy` | top-left + bottom-right | torchvision, IoU math, NMS |
| `cxcywh` | centre + size, often **normalised** | YOLO labels, most one-stage heads |

$$\text{xywh} \to \text{xyxy}: (x,\,y,\,x{+}w,\,y{+}h) \qquad \text{xyxy} \to \text{cxcywh}: \left(\tfrac{x_1+x_2}{2},\, \tfrac{y_1+y_2}{2},\, x_2{-}x_1,\, y_2{-}y_1\right)$$

<ConceptBox title="Why this bug is so hard to see">
Feed `xywh` into code expecting `xyxy` and nothing crashes — the numbers are all plausible. The box simply lands in the wrong place, IoU with the ground truth comes out low, and the model trains to a mediocre mAP that looks like an architecture problem. **Always visualise a handful of boxes on their images before training.** Ten minutes there saves a week of tuning.
</ConceptBox>

## Getting regions without a network

For a controlled scene — a conveyor belt, a document, a colour-coded part — classical segmentation gives you boxes directly:

```python
import cv2, numpy as np

hsv  = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)
mask = cv2.inRange(hsv, (35, 80, 60), (85, 255, 255))          # green range (Module 1)

# clean the mask: opening kills specks, closing fills pinholes
k    = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))
mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN,  k)
mask = cv2.morphologyEx(mask, cv2.MORPH_CLOSE, k)

contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
boxes = [cv2.boundingRect(c) for c in contours if cv2.contourArea(c) > 200]   # (x, y, w, h)
```

`RETR_EXTERNAL` keeps only outermost contours — otherwise a ring gives you two. The area filter is the poor relation of a confidence threshold.

**Morphology, in one line each:** *erosion* shrinks white regions, *dilation* grows them; *opening* (erode then dilate) removes small white specks; *closing* (dilate then erode) fills small black holes.

## Worked example — clipping a box to the image

A detector predicts `xyxy = (-12, 40, 655, 500)` on a 480×640 image. Clip before slicing:

$$x_1 = \max(0, -12) = 0, \quad x_2 = \min(640, 655) = 640, \quad y_2 = \min(480, 500) = 480$$

Width went from $655 - (-12) = 667$ to $640$ and height from 460 to 440, so the area drops from $306{,}820$ to $281{,}600$ — an **8.2% loss** the model never sees unless you clip explicitly. Predicted boxes routinely extend past the frame because the regressor has no notion of image bounds; clipping is a required post-processing step, not an optional one.
