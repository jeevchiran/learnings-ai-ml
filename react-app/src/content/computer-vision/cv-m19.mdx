## The multi-scale idea

YOLO v1 predicts from one $7\times7$ map. Every object, from a distant pedestrian to a bus filling the frame, must be described by a cell of one fixed receptive field. That is the root of both its weaknesses.

<PredictReveal
  prompt="SSD replaces YOLO's single 7×7 map with predictions from six feature maps at different depths of the backbone. Which maps catch the small objects?"
  options={["The early, high-resolution maps", "The late, coarse maps", "All six equally — resolution doesn't matter"]}
  correct={0}
>

SSD attaches a small **prediction head — a $3\times3$ convolution** — to six feature maps at different depths:

<SSDPyramidWidget />

Each head outputs, per cell and per default box, $(C+1)$ class scores and 4 offsets. So a layer with a $m \times n$ map and $k$ boxes per cell emits

$$(C + 1 + 4) \times k \times m \times n$$

values, all convolutionally — no dense layers, so the whole detector is fully convolutional in the sense of Module 11.

</PredictReveal>

Early high-resolution maps have small receptive fields and handle small objects; deep coarse maps handle large ones. It gets multi-scale detection from the network's own hierarchy, with no image pyramid and no extra forward passes." },
]} />

## Default box scales

For $m = 6$ prediction layers, with $s_{\min} = 0.2$ and $s_{\max} = 0.9$:

$$s_k = s_{\min} + \frac{s_{\max} - s_{\min}}{m - 1}(k - 1), \qquad k = 1 \dots m$$

giving $0.20,\, 0.34,\, 0.48,\, 0.62,\, 0.76,\, 0.90$ — linearly spaced fractions of the image. At each scale, aspect ratios $a \in \{1, 2, 3, \tfrac12, \tfrac13\}$ give

$$w_k^a = s_k\sqrt{a}, \qquad h_k^a = \frac{s_k}{\sqrt{a}}$$

plus one extra square box of scale $\sqrt{s_k s_{k+1}}$, which is where "6 boxes per cell" comes from (5 ratios + 1 extra); layers using only $\{1, 2, \tfrac12\}$ get 4.

Note $w \cdot h = s_k^2$ for every ratio — **the area is held constant and only the shape varies**. Scale is the feature map's job, aspect ratio is the default box's.

<Recall items={[
  { q: "Default boxes at one layer share a scale but vary in aspect ratio. What does that split buy?", a: "It separates two independent variables cleanly. The feature map's resolution and receptive field determine what size of object a cell can see, so scale is the map's job; the default boxes then only have to cover shape at that scale, using w = s*sqrt(a) and h = s/sqrt(a), which keeps the area equal to s² for every ratio. That way adding aspect ratios does not disturb the scale assignment." },
]} />

## Matching and the imbalance problem

Matching is Module 18's rule: each ground truth takes its best-overlapping default box, plus **any** default box with IoU > 0.5 (so one object may have several positives, which improves recall).

<PredictReveal
  prompt="Of SSD300's 8,732 default boxes, a typical image matches only about 10 to a real object — roughly 0.11% positive. Train on all 8,732 unweighted, and what happens?"
  options={["Works fine — the 8,722 easy negatives just add stable signal", "The background class dominates the loss and the model fails to train", "The model automatically down-weights unmatched boxes on its own"]}
  correct={1}
>

Then the arithmetic bites. Of 8,732 boxes, a typical image matches perhaps 10:

$$\frac{10}{8732} \approx 0.11\% \text{ positive}$$

Training on all of them, the background term dominates by ~1000×. SSD's fix is **hard negative mining**: sort the negatives by their confidence loss (most-wrongly-confident first), keep only the worst ones, capped at 3 negatives per positive. The paper reports this both stabilises optimisation and speeds convergence.

$$L = \frac{1}{N}\left(L_{\text{conf}} + \alpha L_{\text{loc}}\right), \qquad \alpha = 1$$

with $N$ the number of matched boxes — and if $N = 0$ the loss is set to 0 rather than dividing by zero.

</PredictReveal>

<Recall items={[
  { q: "Why does SSD need hard negative mining when Faster R-CNN's head does not?", a: "Because SSD computes a loss over every one of its 8,732 default boxes, of which roughly 0.1% are matched to an object, so the background term outweighs the positives by about a thousand to one. Faster R-CNN's second stage is trained on a sampled, roughly balanced minibatch of a few hundred RoIs, so the imbalance never reaches the loss. SSD sorts negatives by confidence loss and keeps only the worst, capped at 3 per positive." },
]} />

<ConceptBox title="Where SSD still loses">
**Small objects**, despite everything. conv4_3 is shallow and its features are semantically thin, so a 20-pixel object gets a fine grid but a weak descriptor. The SSD paper's own error analysis says so, and recommends more aggressive random-crop ("zoom out") augmentation as a partial fix.

FPN is the real answer: instead of predicting from raw shallow layers, build a top-down pathway that gives *every* resolution deep semantics. Every serious detector since 2017 — RetinaNet, YOLOv3 onward, EfficientDet — has an FPN or a descendant of one.
</ConceptBox>

<DerivationSteps>
<DerivationStep number={1} title="Counting SSD300's outputs">

Per layer, the head emits $k(C + 5)$ channels — $k$ default boxes, each with $C+1$ class scores (including background) and 4 offsets. For VOC, $C = 20$, so $C + 1 + 4 = 25$ per box.

Total default boxes:

$$38^2(4) + 19^2(6) + 10^2(6) + 5^2(6) + 3^2(4) + 1^2(4)$$
$$= 5776 + 2166 + 600 + 150 + 36 + 4 = \mathbf{8{,}732}$$

Total numbers emitted: $8{,}732 \times 25 = 218{,}300$ per image — against YOLO v1's 1,470. Both are one forward pass; SSD simply reads out more, because reading out more of an already-computed feature hierarchy is nearly free. The expensive part is the backbone, and they share it.

SSD512 uses one extra prediction layer and a larger input, giving 24,564 boxes: more small-object coverage, at 22 fps instead of 59.

</DerivationStep>

<DerivationStep number={2} title="Why the scale formula is linear in k, and what that assumes">

$$s_k = s_{\min} + \frac{s_{\max} - s_{\min}}{m-1}(k-1)$$

Feature-map *resolution* halves geometrically (38, 19, 10, 5, 3, 1) while default box *scale* grows linearly (0.20 … 0.90). Those do not match, and that is intentional: object scale in natural images is not uniformly distributed, and the linear spacing puts more distinct scales in the small-to-mid range where most objects live.

The assumption underneath is that **receptive field grows fast enough to cover the assigned scale**. Each successive map has roughly double the receptive field, so by conv11_2 a single cell sees essentially the whole image — appropriate for $s_6 = 0.9$. If you retarget SSD to a dataset of uniformly tiny objects, the deep layers' boxes never match anything and two-thirds of the network's capacity is idle. That is when you re-derive the scales for your data, exactly as Module 18 re-derives anchors.

</DerivationStep>
</DerivationSteps>

<ConceptBox title="TL;DR">
- SSD keeps YOLO's one-pass idea and fixes its scale problem: predict from **six feature maps of decreasing resolution**, not one.
- Early, high-resolution maps have small receptive fields and catch small objects; late, coarse maps catch large ones. No image pyramid needed.
- Default boxes (SSD's word for anchors) follow $s_k = s_{\min} + \frac{s_{\max}-s_{\min}}{m-1}(k-1)$ from 0.2 to 0.9.
- SSD300 scores **8,732 boxes** per image against YOLO v1's 98 — and reaches **74.3 mAP at 59 fps**, beating Faster R-CNN on both axes.
- 8,732 boxes are ~99.9% background, so **hard negative mining at 3:1** is not a tuning detail; without it the model does not train.
</ConceptBox>
