## Numerical Data: End-to-End

The most common workflow — a gradient-boosted tabular model, explained exactly with Tree SHAP:

```python
import shap
from xgboost import XGBRegressor
from sklearn.datasets import fetch_california_housing
from sklearn.model_selection import train_test_split

X, y = fetch_california_housing(return_X_y=True, as_frame=True)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)
model = XGBRegressor(n_estimators=400, max_depth=4).fit(X_tr, y_tr)

explainer = shap.TreeExplainer(model)
sv = explainer(X_te)                 # SHAP values for every test row (exact)

# One prediction, explained:
shap.plots.waterfall(sv[0])          # base value → this row's prediction, step by step
# The whole model:
shap.plots.beeswarm(sv)              # global importance + direction across all rows
shap.plots.scatter(sv[:, "MedInc"])  # how median income's effect varies (dependence)
```

The base value is average house price; the waterfall shows how *this* neighbourhood's median income, location, and occupancy push the prediction up or down to its final value. **Verify additivity yourself** — it's a one-liner:

```python
import numpy as np
assert np.allclose(sv.values.sum(1) + sv.base_values, model.predict(X_te), atol=1e-4)
# SHAP values + base == model prediction, for every row
```

<ConceptBox title="A caution on correlated features">
When features are strongly correlated, marginalising one "absent" feature can produce unrealistic inputs (e.g. `rooms=8` with `bedrooms=1`), and SHAP may split credit between them in ways that look surprising. It's not a bug — SHAP is being fair to the *model's* behaviour, including on inputs the correlation makes rare. Interpret correlated features as a *group*, not in isolation.
</ConceptBox>

## Image Data: A "Feature" Is a Region

For an image classifier there are too many pixels to treat each as a feature, so SHAP groups them — into superpixels (masked regions) or evaluates per-pixel via gradients. Absent pixels are replaced by a **baseline** (blurred image, grey, or dataset mean). The result is a heatmap: red where pixels *supported* the class, blue where they *argued against* it.

```python
import shap, torch

# model: a trained image classifier (e.g. torchvision CNN), preprocessed inputs
masker = shap.maskers.Image("inpaint_telea", X_img[0].shape)  # how to "remove" pixels
explainer = shap.Explainer(model_predict, masker, output_names=class_names)

sv = explainer(X_img[:2], max_evals=3000, batch_size=64)
shap.image_plot(sv)   # overlays red/blue SHAP heatmap on each image
```

For deep nets specifically, **Deep SHAP** (a DeepLIFT-based estimator) is far faster than masking:

```python
background = X_img[:100]                      # reference distribution
de = shap.DeepExplainer(model, background)    # torch or TF model
shap_vals = de.shap_values(X_img[100:104])
shap.image_plot(shap_vals, X_img[100:104])
```

<ConceptBox title="This is how you catch a cheating vision model">
Run SHAP on a "dog vs. wolf" classifier and the heatmap lights up the **snow in the background**, not the animal — the model learned "snow ⇒ wolf." No accuracy number reveals this; the pixel-level attribution does immediately. Image SHAP is a debugging tool as much as an explanation.
</ConceptBox>

## Practice

#### Problem 1: What replaces "absent" pixels?
In image SHAP you can't literally delete a pixel. What happens to "absent" pixels, and why does the choice matter?

**Solution:** Absent pixels are replaced by a **baseline** — a blurred version, grey, inpainting, or the dataset mean — because SHAP must still feed the model a full image. The choice matters because SHAP measures contributions *relative to that baseline*; a different baseline ("what does absent mean?") shifts the attributions, just as the background dataset does for tabular Kernel SHAP.

#### Problem 2: Reading an image heatmap
A cat classifier's SHAP heatmap shows strong red over a text watermark in the corner and little over the cat. What do you conclude?

**Solution:** The model is keying on the **watermark**, not the cat — a spurious correlation (likely a data leak where that watermark co-occurs with the class). Despite possibly high accuracy, the model isn't learning the intended concept. Fix the data (remove/randomise the watermark) and retrain.
