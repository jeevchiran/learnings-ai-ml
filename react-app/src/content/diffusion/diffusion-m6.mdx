## Ancestral sampling, one step at a time

<PredictReveal
  prompt="Training picks a random timestep and jumps straight to x_t using the closed-form shortcut from Module 2. Can sampling use the same shortcut to jump straight to x_0 from pure noise?"
  options={["Yes — the same closed-form formula works in reverse", "No — the closed form requires knowing x_0 already, which is exactly what sampling doesn't have; sampling must walk the chain step by step"]}
  correct={1}

<ReverseDenoisingWidget />

Sampling starts from $x_T \sim \mathcal{N}(0, I)$ — pure noise, no information about any particular image — and applies the learned reverse step $p_\theta(x_{t-1}|x_t)$ repeatedly: predict the noise with $\epsilon_\theta(x_t, t)$, use it to estimate a slightly-less-noisy $x_{t-1}$, and repeat, all the way down to $x_0$. There is no shortcut here because the closed form from Module 2 requires $x_0$ as an input — which is precisely the thing sampling is trying to produce.

</PredictReveal>

<Recall items={[

Sampling starts with no x_0 at all — producing one is the entire point — so it has nothing to plug into the shortcut and must instead walk the reverse chain step by step, using the learned network at each step." },
]} />

## Why this is diffusion's real cost

<PredictReveal
  prompt="If T = 1000 and every reverse step requires one U-Net forward pass, how many total network evaluations does producing a single image require?"
  options={["One, since the U-Net was trained to handle all timesteps at once", "Up to 1000 — one full network pass per reverse step, executed in strict sequence"]}
  correct={1}
>

Every single step is a full forward pass through the U-Net, and step $t-1$ needs step $t$'s output before it can run — there is no way to parallelize across steps. For a typical $T$ in the hundreds to low thousands, this means hundreds to thousands of sequential network evaluations per generated sample, which is exactly the cost Module 1 previewed and the reason diffusion sampling is dramatically slower than a GAN's single forward pass. Module 7 covers the two standard ways to cut this cost without retraining the model.

</PredictReveal>

<Recall items={[
  { q: "Why can't the T sequential reverse steps be parallelized to speed up sampling?", a: "Each reverse step's output x_{t-1} is required as the input to compute the next step's x_{t-2}, so the steps form a strict sequential dependency chain. There is no way to compute a later step before an earlier one has finished, unlike operations that act independently across a batch." },
]} />

---

<ConceptBox title="TL;DR">
- Sampling starts from pure noise $x_T \sim \mathcal{N}(0, I)$ and walks the reverse chain **step by step**, since the Module 2 shortcut needs $x_0$ as input — exactly what sampling doesn't have yet.
- Every reverse step is one full U-Net forward pass, and each step's output is required before the next step can run — the chain cannot be parallelized.
- For $T$ in the hundreds to thousands, this means hundreds to thousands of **sequential** network evaluations per sample — the concrete source of diffusion's sampling-speed disadvantage against a GAN's single pass.
</ConceptBox>
